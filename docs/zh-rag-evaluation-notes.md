# 中文 RAG 评测踩坑记录

本文整理用 Ragas 0.1.21 评测中文 RAG 回答时实际遇到的问题。每一条都标出依据，分清「已确认」和「仅观察到、原因未确认」。素材全部来自本仓库的运行证据，题目只来自单一金融材料（《存款保险条例》节选），不能推广成通用结论。

## 1. 中文回答的陈述可能被整句丢掉（已确认，已修正）

**现象**：中文兼容修正之前的 5 题预跑中，Faithfulness 有 2/5 缺失，Trace 有 2/5 为空。
（[预跑证据](competition/evidence/20261005T101847Z-pilot-c72cb679/README.md)）

**原因**：Ragas 0.1.21 在 Faithfulness 和 Answer Correctness 中，分句之后只保留以英文句号结尾的句子。中文以「。」结尾，于是整段回答没能进入陈述抽取提示，指标随之缺失或失真。

**处理**：[`backend/adapters/ragas_compat.py`](../backend/adapters/ragas_compat.py) 的 `zh-sentence-v1` 做了三处限定：

- 只对含中文字符的文本，把非空分句按原顺序编号送入原有提示；
- 纯英文文本继续走原实现；
- 不改评分公式、权重和裁判提示，也不改动 Ragas 全局单例。

模块加载时会核对 Ragas 版本，不是 0.1.21 就直接报错，避免依赖升级后静默失效。

**验证**：修正后的 5 题技术验证中，15 条句子抽取提示都完整包含中文输入，五项指标各 5/5 有效。
（[修正后验证](competition/evidence/20261005T131353Z-pilot-35f623cb/README.md)）

**建议**：用 Ragas 评测中文时，先抽查陈述抽取提示里是否真的带上了回答原文，再看分数。只要指标出现缺失，就应先排查输入，而不是直接当作模型表现。

## 2. 回答和上下文都不变，分数也可能变（仅观察到，原因未确认）

**现象**：修正前后两次运行中，C05 的问题、参考答案、有序检索上下文和回答完全相同，但下面两项指标仍有变化。

| 指标 | 修正前 | 修正后 | 备注 |
|---|---|---|---|
| Answer Correctness | 0.7937 | 0.9437 | |
| Context Precision | 0.5000 | 1.0000 | 这一项不经过句子适配 |

（[修正后验证分析](competition/evidence/20261005T131353Z-pilot-35f623cb/analysis.md)）

**能说的**：这两次运行没有控制住裁判模型的全部输出，不是消融实验，**不能把分数变化归因于兼容修复**。裁判本身存在波动，这一点可以确认；具体是哪个因素造成了这次变化，目前未确认。

**建议**：同一题的单次分数差异不足以说明改动有效。对比不同版本时，应固定输入，多跑几次，看分布而不是看单次。

## 3. 拒答时，Faithfulness 0 不等于答错（已确认的口径问题）

**现象**：修正后，N01、F03 两条拒答的 Faithfulness 由「缺失」变为 0，而它们的 Trace 是「没有陈述」。
（[修正后验证分析](competition/evidence/20261005T131353Z-pilot-35f623cb/analysis.md)）

**含义**：拒答没有可核对的事实陈述，Faithfulness 给出 0，这只是指标口径的结果，并不证明拒答错误。负向题（文档未提及的问题）中，拒答恰恰是正确行为。

**处理**：本项目的门禁只用正向样本均值，负向样本不参与门禁；页面按样本类型区分「正确拒答」和「缺失 / 无法评估」。指标定义和原分数保持不变，没有为了 PASS 调整口径。

## 4. 空 Trace 不等于没有幻觉

25 题正式运行中，Trace 非空 18 条、空 7 条。
（[正式运行证据](competition/evidence/20261005T144504Z-full-39511424/README.md)）

空 Trace 可能来自拒答，也可能来自陈述抽取为空。它既不能证明没有幻觉，也不能单凭它认定调用失败。逐句判定依赖裁判模型的输出，本身也不是独立的真实性保证。

## 5. 请求的模型不一定是实际返回的模型

正式运行请求的是 `deepseek-chat`，325 次调用的实际返回模型均记录为 `deepseek-flash`。评测记录应同时保存「请求模型」和「实际返回模型」，否则后续对照时可能比错对象。

## 6. 裁判与被评模型同源

当前后端用被评模型兼任 Ragas 的裁判和 Trace 的裁判。作者在 13 条定向样本上做了人工核验，其中 5 条与机器判定存在分歧。这说明同源裁判的结论需要人工对照，但这 13 条样本不能用来计算总体准确率。换用独立裁判后的量化对照见 [独立裁判对照](judge-comparison.md)；改进方向见 [路线图](../ROADMAP.md) 第一阶段「独立裁判」。
