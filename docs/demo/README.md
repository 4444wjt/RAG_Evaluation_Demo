# 演示指南

## 无密钥展示

在 `frontend/` 执行 `npm ci`、`npm run dev`，打开 `http://127.0.0.1:5173/`，点击“查看演示”。也可直接访问 `http://127.0.0.1:5173/#/lab/demo`。

首页和演示快照不需要后端或模型密钥，不发起真实评测。工作台可能进行健康检查，未启动后端时的服务提示不影响快照展示。

## 推荐顺序

1. **首页**：用五步流程解释问题、检索上下文、模型回答、核对证据和质量门禁。
2. **总览**：读模型、样本范围、两项正向门禁指标和阈值，再查看风险 KPI 与能力图。
3. **多模型对比**：展示 DeepSeek、Qwen2.5-7B、GLM-5.2-Fast 的已有指标和耗时，不将某一个指标等同于总体排名。
4. **幻觉分析**：从问题进入回答、逐句判定、原始证据和检索上下文。
5. **评测验证**：区分机器原判定与人工材料，再展开真实历史 FAIL，按问题、回答、指标与门禁顺序说明。
6. **报告**：手动选择本地生成的 HTML；导入报告与当前结果的对应关系须由演示者确认。
7. **工作区**：说明真实评测的文档、测试集、模型和阈值配置。只有明确需要真实调用时才开始评测。

## 评测可信度展示

- **演示门禁范围**：快照含 6 个独立问题、3 个模型、18 条回答；当前门禁卡检查所选模型的 3 条正向用例。首页 PASS 用于展示流程，不代表总体可靠性。
- **人工核验入口**：加载演示后进入左侧“评测验证”。当前预选 13/18 条回答，作者 Kk 于 2026-10-05 完成逐条检查：一致 3 条、存在分歧 5 条、无法确认 5 条，待核验 0 条、未纳入 5 条。AI 仅辅助整理材料；覆盖数不是准确率，也不代表独立复核或系统认证。
- **历史失败案例入口**：展开“查看问题、指标与门禁依据”，先读三个问题与原始回答，再看逐条指标和原始 FAIL。第二个问题上下文精度为 33.3%，归档正向均值 0.7778 低于 0.8 门槛；这不等于确认回答事实错误。

金融案例来自不同的旧 CLI 运行，未保存原始门禁说明或 Trace，不并入当前核验范围、不作为当前 Web API 复跑证明。PASS、Trace、Judge、人工材料及缺失信息的集中说明见 [评测结果可信度与限制](../evaluation-credibility.md)。

### 录入真实人工核验材料

核验页只读。真实检查完成后，在 [`credibility-review.json`](../../frontend/src/fixtures/credibility-review.json) 的现有记录录入核验者、实际日期、回答级理由和逐句人工结论；机器快照、13 个记录键、版本与 SHA-256 保持不变。未完成的记录继续为空，不代填结论。

使用未核验／一致／分歧／无法确认四种状态；明确分歧与未决项并存时汇总为分歧。“一致”不能与明确遗漏、拒答问题、无法确认项或不同逐句判定并存。完整字段表、状态规则及档案检查要求见 [人工核验范围与录入规则](../evaluation-credibility.md#3-人工核验范围与录入规则)。

## 出处与限制

- 首页预览来自已有快照 `20260930-1958`，原文、状态、模型 ID 和数值未修改。
