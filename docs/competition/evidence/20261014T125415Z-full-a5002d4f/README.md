# 独立裁判复核：换一个裁判模型重跑 25 题（2026-10-14）

**结论：** 换成独立裁判后，门禁回到 **FAIL**。

- 生成模型不变（`deepseek-chat`），Ragas 裁判与逐句核对改用另一家的 `Qwen/Qwen2.5-72B-Instruct`。
- 正向忠实度 `0.7992`，低于阈值 `0.8`。同一修复版本在 [10-14 修复验证](../20261014T073859Z-full-1c6f091f/README.md)（生成与裁判同为 DeepSeek）中是 `0.8607`，门禁 PASS。
- 所以 **10-14 的 PASS 依赖裁判模型**，不能单独作为「修复已让门禁稳定通过」的证据。两次的 95% 区间都跨过 `0.8`，结论确定性都是「证据不足」。

## 为什么做这次运行

10-14 修复验证里，回答由 DeepSeek 生成，打分也由 DeepSeek 完成，存在「自己评自己」的嫌疑。平台已支持把裁判单独配置为另一个模型（`run_evidence.py --judge-model`），这是该能力的第一次真实运行。

## 运行方式

```bash
python tools/competition/run_evidence.py --batch full --model deepseek-chat --judge-model Qwen/Qwen2.5-72B-Instruct --execute
```

- 裁判模型在本机 `models.local.json`（不入库）登记，密钥只从本地 `.env` 读取。
- 题集、资料、检索参数、门禁代码与阈值和 10-14 相同：`manifest.json` 记录的 `backend/core/gate.py`、`backend/services/answering.py`、`scenarios/competition_25/testset.json` 哈希与 10-14 归档一致。
- 源码为提交 `1d43c10` 加上尚未提交的独立裁判支持代码，逐文件哈希见 `manifest.json`。

门禁回放与回归对比：

```bash
python scripts/gate_replay.py docs/competition/evidence/20261014T125415Z-full-a5002d4f/api-response.json --baseline docs/competition/evidence/20261014T073859Z-full-1c6f091f/api-response.json
```

输出见 [`gate-replay-vs-baseline.txt`](gate-replay-vs-baseline.txt)：归档记录 FAIL，回放 FAIL，一致。

## 结果

| 指标 | 10-14（DeepSeek 自评） | 本次（Qwen2.5-72B 裁判） |
|---|---:|---:|
| 门禁 | PASS | **FAIL** |
| 正向忠实度（门禁指标） | 0.8607 | **0.7992** |
| 正向忠实度 95% 区间 | 0.7286–0.9667，证据不足 | 0.675–0.91，证据不足 |
| 正向上下文精度（门禁指标） | 0.9833 | 0.9556 |
| 拒答准确率 | 1.0 | 1.0 |
| 答案正确性（25 题平均） | 0.7296 | 0.5774 |

### 分数变化来自哪里

生成模型温度为 0，但两次回答并不完全相同：25 题中 18 题回答逐字相同，7 题不同（D09、C01、C02、C05、F03、F04、F05）。

- **回答相同的 13 道正向题**：DeepSeek 自评平均 `0.9377`，Qwen 裁判平均 `0.8718`。回答一字未改，分数降了约 `0.07`，这部分只能归因于裁判。例如 D03、D10、F02 都从 `1.0` 降到 `0.5`；D08 反过来从 `0.33` 升到 `1.0`。
- **回答不同的题**：
  - F04 这次没有拒答，指出了「7 个工作日」而不是「7 个自然日」，但把条文说成「第十八条相关条款」。节选里没有第十八条，Qwen 裁判把这句判为编造，判断正确。
  - F03、F05 的纠正内容和 10-14 基本一致，忠实度却从 `1.0`、`0.86` 降到 `0.2`。逐句核对把 F03 的「问题中的说法与参考资料不一致」判为事实错误，这是裁判误判：这句话正是在指出错误前提。

### 逐句核对

- 25 题中 15 题核对完成、2 题部分完成、3 题是负向题的空回答；**D01–D05 共 5 题因供应商限流（RateLimitError）核对失败**，没有逐句结果。
- 已核对的 39 条陈述中，1 条判为事实错误（F03，见上），3 条判为编造（F04 一条成立；N04、N05 的拒答句「无法回答该问题」被判为编造，属于裁判误判）。
- 逐句核对不参与门禁，这些缺失不影响门禁结论；缺失按缺失记录，没有补零。
- **同一裁判的两种核对互相矛盾。** D10、C01、C02、F02、F05 的逐句核对全部判为有依据，同一裁判给出的忠实度却只有 `0.2`–`0.75`。门禁用的是忠实度，所以这些题拉低了门禁分数。原因未核实；[外部 RAG 端到端实测](../../external-rag/20261014-example-app-qwen72b/README.md)中同一裁判也出现了同样的情况。

## 能说明什么，不能说明什么

**能说明：**
- 裁判换成另一家模型后，门禁结论会翻转。10-14 的 PASS 不能脱离裁判单独成立。
- 平台的独立裁判配置在真实运行中可用：生成与裁判的返回模型分别记录（`deepseek-flash` 25 次，`Qwen/Qwen2.5-72B-Instruct` 295 次）。

**不能说明：**
- 不能说明哪个裁判更准。两个裁判都有误判（DeepSeek 的 D08，Qwen 的 F03、N04、N05），要判断需要人工标注对照。
- 只跑了一次。回答在温度 0 下仍有 7 题不同，裁判本身也有波动。
- 没有用 Qwen 裁判重新评分 10-14 的原回答；那样可以把「回答变化」和「裁判变化」完全分开，本次没有做。
- 只有一个领域、一个生成模型。
