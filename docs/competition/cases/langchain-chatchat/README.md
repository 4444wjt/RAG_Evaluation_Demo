# 外部案例：Langchain-Chatchat 默认知识库提示词遇到错误前提题

本项目的 [失败归因](../../../gate-replay.md#失败归因该修检索还是生成) 发现：25 题正式运行的 FAIL，主要来自错误前提题。资料里有依据，模型却回答「无法回答」，而问答提示词只给了「无法回答」这一个出口。

本案例检验一个外部项目：流行开源 RAG 项目的默认提示词，会不会有同样的问题。

**已运行一次（2026-10-14）。** 付费调用经用户在会话中授权：预算 ¥2，最多 120 次请求，不重试。授权见 [authorization.json](authorization.json)。

## 做法

- **被测对象**：[Langchain-Chatchat](https://github.com/chatchat-space/Langchain-Chatchat)，提交 `49165d6af4438aa7e8a1f71ce276db55f4405151`，许可证 Apache-2.0。
  - 默认知识库问答模板取自 `libs/chatchat-server/chatchat/settings.py` 的 `PromptSettings.rag["default"]`，逐字引用。
  - 按它的 `kb_chat.py` 拼装：资料用空行连接，整段作为一条用户消息。
- **对照组**：本项目自己的问答提示（`backend/services/answering.py` 的 `rag_answer`），与被测组在同一次运行中重新作答，不拿旧结果比较。
- **只变一个因素**：两组的题目和资料相同，都取自 [25 题正式运行](../../evidence/20261005T144504Z-full-39511424/README.md)，检索结果固定。模型也相同，都是 DeepSeek-V4.1-Flash（请求 `deepseek-chat`，服务端 100 次都返回 `deepseek-flash`），温度 0。
- **每题两次调用**：作答一次，再由平台逐句核对一次。拒答按 `backend/core/attribution.py` 的 `is_refusal` 判定。
- **不计算 Ragas 指标，不给门禁结论**，只比较作答行为和逐句核对结果。

被测模板原文（版权归 Langchain-Chatchat 作者，按 Apache-2.0 引用）：

```text
【指令】根据已知信息，简洁和专业的来回答问题。如果无法从中得到答案，请说 “根据已知信息无法回答该问题”，不允许在答案中添加编造成分，答案请使用中文。

【已知信息】{{context}}

【问题】{{question}}
```

## 说明了什么

1. **同样的问题在外部项目上也出现了。** F03、F04 的资料里都有纠正前提所需的原文，两种提示都回答「无法回答」。这两道题的错误都落在一个细节上（缴费主体、工作日与自然日）。两种提示都把「无法从中得到答案」作为唯一的退路，模型遇到与资料冲突的前提时，选择了这个退路。
2. **Chatchat 的默认提示多纠正了一道**（F01）。只有 5 道题，相差 1 道，不能说明哪个提示更好。
3. **不用本平台很难发现这个问题。** 拒答在 Ragas 忠实度里同样记为低分，与编造看不出区别。本平台把「拒答」和「编造」分开，并给出资料里的原文依据，所以能指出问题出在提示词，而不在检索或模型。
4. **单次运行的逐题结论会波动。** 同样是本项目的提示，正式运行拒答了 4 道（F01、F03、F04、F05），这次拒答了 3 道，F05 改为纠正。两次温度都是 0，提示词和资料也相同。温度 0 不能保证每次输出一样，所以逐题结论应以多次运行为准。

## 不能说明什么

- 这里测的只是**默认提示词**，不代表 Langchain-Chatchat 实际部署的效果。用户可以修改模板，项目还有自己的检索流程。本案例固定了检索结果，只换提示词。
- 一个领域、一个模型、25 题、一次运行。不给被测项目打总分，也不排名。
- 本次**没有测试修改后的提示词**，所以不能断言「加一句允许纠正前提」就能解决 F03、F04。这一点要另外运行才能确认。

## 复算

```bash
python tools/competition/prompt_case.py prepare   --dir <工作目录>
python tools/competition/prompt_case.py authorize --dir <工作目录> --by <授权人> --budget 2 --max-requests 120
python tools/competition/prompt_case.py run       --dir <工作目录>
python tools/competition/prompt_case.py analyze   --dir <工作目录> --output <归档目录>
```

- `prepare` 不调用模型。同一提交下生成的材料包相同，本次材料包的 SHA-256 记录在 `authorization.json` 中。
- 模型输出不固定，重跑的逐题结果可能不同。
- **运行后改动**：运行后只修改了工具的分析部分。拒答没有可核对的陈述，原先被列为「核对失败」，现改为单独统计，不算失败。运行时的工具副本存于 [runner/prompt_case.py](runner/prompt_case.py)，其哈希与 `authorization.json` 中记录的一致。
