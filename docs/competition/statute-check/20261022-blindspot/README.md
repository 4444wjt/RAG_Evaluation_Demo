# 裁判盲区体检：第二部法规上的款级盲区与补标签（2026-10-22）

**结论：** 换一部法规（《中华人民共和国政府信息公开条例》节选；补标签对照用的是存款保险材料），由程序自动构造引用错误题，同一个通用裁判（DeepSeek `deepseek-flash`，关闭思考，原提示）：

- **原节选下（不补标签）：**
  - 条号引错 10 条，全部检出（10/10）；
  - 只把款号引错 10 条，只检出 1 条（1/10）。
- **补标签后**：只给节选的每一款补上「第X条第Y款」标签，其余逐字不变，同样 10 条款级错误全部检出（10/10）。
- **误报**：两种条件下，正确引用的对照都是 0/5。
- **判定**：按运行前登记的四条阈值，四条同时满足，记为**成立**。
- **运行**：40 次请求全部有效，失败 0、未执行 0；单次运行。
- 本结果不参与 Quality Gate，不改门禁和历史 FAIL 结论。

## 为什么做

[补标签对照](../20261022-labeled/README.md)是在存款保险材料上做的，题目由人工编写。补标签后，DeepSeek 的款级检出从 3/31 升到 23/31；但「不存在的款」只有 8/13，主张记为部分成立。

这次要回答两个问题：

1. 换一部法规、换成程序出的题，「原节选下款级看不见、补标签后看得见」还会不会出现？
2. 条级错误能检出、款级错误检不出，这种分层是否同时成立？

## 运行前登记的阈值

阈值在出题和运行之前写定。登记文件的 SHA-256 为 `3703256a6e24f2a1c848a772638d7f71286896843ddfd4682239fc72a47f4d06`，`run/package/package.json` 的 `registration` 字段和 `run/authorization.json` 都绑定了这个值。登记文件本身含内部评估内容，没有随本目录公开；四条阈值照录如下：

| 阈值 | 条件 | 成立要求 |
|---|---|---|
| 盲区重现 | 不补标签，款级错误 | 检出 ≤ 3/10 |
| 干预有效 | 补标签，款级错误 | 检出 ≥ 7/10 |
| 结果可用 | 两种条件下的对照，各自计 | 误报 ≤ 1/5 |
| 分层成立 | 不补标签，条级错误 | 检出 ≥ 7/10 |

- 四条同时满足才算成立；任何一条在界外，包括落在 4–6/10，都记为不成立。
- 检出指裁判判为 `contradicted` 或 `insufficient`。
- 失败或解析失败单列为不可用，不算作未检出；分析时把不可用分别按「检出」和「未检出」各算一遍，两种算法结论相同才记为稳定（`robust`）。

## 做了什么

**材料**：

- 法规：`scenarios/information_disclosure.txt`，即《中华人民共和国政府信息公开条例》第二十九至三十四条、第三十七、三十八、四十二条节选，共 13 款。
- 出题：由 `prep/make_exam.py` 按登记的规则机械出题，共 25 条陈述。
  - 陈述写法统一为「按照<所引条款>规定，<内容>」；
  - 内容逐字取自原文，只改其中的引用。
- 标签：真值由构造决定，不来自规则。

| 类型 | 条数 | 怎么改 |
|---|---:|---|
| 同条另一款 | 7 | 内容来自某款，引成同条的另一款 |
| 不存在的款 | 3 | 引成该条没有的款号 |
| 换成另一条 | 5 | 引成节选中的另一条 |
| 节选外的条 | 5 | 引成条例中存在、但节选里没有的条 |
| 正确引用对照 | 5 | 引用正确 |

**两种条件**：

- **U（原节选）**：使用完整原节选，25 条全跑。
- **L（补标签）**：
  - 给每一款补上「第X条第Y款」标签，共 13 个；去掉标签后能逐字节还原原节选。
  - 只跑款级错误 10 条和对照 5 条。

**与之前运行的关系**：

- 裁判配置与信息对等运行的 J2 相同：DeepSeek、温度 0、`maxTokens` 768、关闭思考、不重试，原提示也不改。
- 有一处不同：自动出题没有真实用户问题，25 条共用一个中性问句「《中华人民共和国政府信息公开条例》节选对此有什么规定？」，不提示裁判去核对引用。

**运行**：

- 40 次请求全部返回有效结果，停止原因为 `completed`；40 次返回的模型名都是 `deepseek-flash`。
- 费用：按授权单价（输入 ¥2/百万 token、输出 ¥8/百万 token，取定价页的高峰时段价，是上界）估算为 ¥0.129398，授权预算 ¥0.3。这不是账单（`actualBillCny=null`）。

## 这说明什么，不说明什么

- 【事实】同一个裁判、同一个提示：原节选下，条号引错 10/10 检出，款号引错 1/10 检出；只给每款补上标签后，款号引错 10/10 检出，两种条件下对照都没有误报。
- 【推断】这与补标签对照的主张一致：原节选里的款没有可对照的字面标签，裁判因此不核款号。这次换了法规、换成程序出题，现象再次出现，而且这次是全部满足。
- **不说明什么：**
  - **规模小。** 25 条陈述只用到 10 个内容单元，例如第二十九条第一款的内容出现在 5 条陈述里，所以 25 条不是 25 个独立样本。只有一部法规节选、一个裁判、一次运行、温度 0。只报条数，不给区间，不能读成比例估计。
  - **题型窄。** 和以前的注入实验一样，只改引用、不改内容；改写过内容的陈述没有检验。[词面基线](../20261022-lexical-baseline/README.md)说明这类材料在词面上本来就能分开，规则在这里 10/10 也不说明规则判断得更好；何况规则当初就是在这份节选上开发的。
  - **问题字段不同。** 这次用的是中性问句，与 J2 的真实用户问题不同，不能和 J2 的检出数直接相减。
  - **Qwen2.5-72B 没跑。** 本次只验证 DeepSeek。补标签对照里 Qwen2.5-72B 补标签后仍只有 2/31，这次没有复测。
  - **补标签只是诊断手段。** 它是在输入里替裁判把款「标出来」，不是对裁判本身的改进，也不说明真实业务材料都缺款标签。

## 文件与离线复算

- `prep/`：
  - `make_exam.py`：出题脚本。它读取的登记文件在内部材料目录，所以本目录里不能直接重跑；它在生成时的哈希记在 `run/package/package.json` 的 `code.makeExam` 字段。
  - `authorization.template.json`：运行前生成的授权骨架，绑定的哈希与正式授权一致。
- `run/`：付费运行归档：
  - `package/`：完整题包，包括 `requests.jsonl`、原节选 `contexts/plain.txt`、补标签节选 `contexts/labeled.txt`、`rules.json`（规则参照）和 `estimates.json`（费用预估）；
  - `authorization.json`：授权，绑定题包、两份节选、请求、提示、配置、登记文件和工具文件的哈希；
  - `events.jsonl`、`records.json`、`manifest.json`；
  - `sources/`：运行时的工具源码副本；
  - `SHA256SUMS.txt`。
- `analysis/`、`analysis-replay/`：两次离线分析，`analysis.json` 逐字节一致。
- `run.stdout.txt`：运行终端输出。
- 实现：`tools/competition/statute_blindspot.py`；离线测试：`tests/test_statute_blindspot.py`，全部用假传输。
- 顶层 `SHA256SUMS.txt` 覆盖本目录全部文件。

复算分析（不发请求，输出目录必须是新的空目录）：

```bash
python tools/competition/statute_blindspot.py analyze --run docs/competition/statute-check/20261022-blindspot/run --output <新的空目录>
```

`analyze` 先核对归档里的工具源码与当前源码逐字节一致，再校验题包、逐条重建全部请求，然后按事件重建记录、计费与停止原因；任何一项不符即停止。
