# 补标签与切片：裁判在什么输入下会核款号（2026-10-22）

**结论：** 同一批 66 条款项定位材料、同一裁判、同一提示，只给完整节选的每一款补上「第X条第Y款」标签，其余逐字节不变。补标签后，DeepSeek 的款级错误检出从 3/31 升至 23/31，支持对照误报 4/31，正好在预设门槛上。「不存在的款」8/13，没有达到预设的 10/13，主张 1 记为**部分成立**。Qwen2.5-72B 补标签后为 2/31。只给它所引那一款的原文切片时，「同条另一款」检出 18/18，正确定位对照误报 1/13。163 次请求全部有效，失败 0、未执行 0。本结果不参与 Quality Gate，不改门禁和历史 FAIL 结论。

## 为什么做

[信息对等对照](../20261022-equalinfo/README.md)里，给两个裁判换上与规则相同的完整节选后，款级错误仍只检出 3 条与 1 条。这份节选里，条有「第一条　…」这样的标题，项有「（一）」，款却没有任何标签，只靠换行区分。

运行前写定了两个主张，判定门槛写在 `run/package.json` 的 `preregistration`：

- **主张 1**：DeepSeek 原节选下漏判，是因为节选里的款没有可对照的字面标签。补上标签后，款级检出应升到 ≥ 15/31。
- **主张 3**：Qwen2.5-72B 补上标签也不核定位；但只要给它的就是所引那一款，它会比对内容。

## 做了什么

**材料。** 与 10-22 信息对等运行同一批 66 条陈述，逐条相同，节选哈希相同。

**条件 L（补标签）。**
- 给节选的每一款补上「第X条第Y款」，共 18 款、18 个标签：
  - 条标题行写成「第五条第一款　…」；
  - 其余款行在行首加「第五条第二款　」。
- 项行、空行、来源说明一字不变；去掉标签后能逐字节还原原节选。
- 两个裁判都跑：DeepSeek（`deepseek-flash`，关闭思考）和 Qwen2.5-72B。

**条件 S（切片）。**
- 只跑 Qwen2.5-72B，只跑「同条另一款」18 条和「正确定位对照」13 条。
- 上下文换成所引款的原文行及其各项，不补标签。
- 注意，切片里有些带「第X条」标题，有些不带：
  - 第一款的原文行就是条标题行，所以引第一款的切片带标题，引其他款的不带；
  - 带标题的：错误 5/18，对照 8/13。

**只差一处的核对。**
- L 的 132 个请求去掉标签后，与信息对等运行 J2 同条同裁判的请求逐字节相同，包括提示、参数和 `thinking` 字段。
- S 的 31 个请求与 J1 相比，只有 `contexts` 不同：J1 是 4 段检索片段，S 是 1 段切片。

**运行。**
- 163 次请求全部返回有效结果，没有失败、没有重试，停止原因是 `request_limit`（按计划请求数跑完）。
- 实际模型分别是 `deepseek-flash` 和 `Qwen/Qwen2.5-72B-Instruct`。
- 按授权单价估算 ¥0.61518288，授权预算 ¥0.65；不是账单（`actualBillCny=null`）。
- 运行在 `work/` 下完成（`run/authorization.json` 的 `outputDirectory` 记录了当时的位置），之后原样复制到本目录。复制后在本目录重跑离线分析，结果与 `analysis/analysis.json` 逐字节相同。

授权原文（照录 `run/authorization.json` 的 `note`）：

```text
基线补标签实验授权：授权人 Ll，日期 2026-10-22。
预算上限 ¥0.65（主张 1 约 ¥0.55 + 主张 3 切片约 ¥0.1），请求前预留、超限即停、不重试。

材料：66 条款项定位材料，与 10-22 信息对等运行同一批（逐条相同、节选哈希相同）。
干预：给节选每一款补上「第X条第Y款」标签，其余一字不变。
对照：同一裁判、同一提示、同一材料，仅加标签这一处差异。

裁判：DeepSeek（deepseek-flash，关思考）+ Qwen2.5-72B。
预期：DeepSeek 款级检出从 3/31 升至 ≥15/31、误报 ≤4/31；Qwen 补标签后仍 ≤5/31，切片后 ≥15/18。
推翻门槛以报告所定为准，结果不利照实记录。

```

Qwen2.5-72B 的单价沿用信息对等运行同日核实的值；本次运行前重查时，定价页没能抓取，`run/authorization.json` 的价格来源里写明了这一点。

## 结果

检出指裁判判为 `contradicted` 或 `insufficient`，只报条数。

| | 款级错误检出（/31） | 其中不存在的款（/13） | 其中同条另一款（/18） | 支持对照误报（/31） | 判定 |
|---|---:|---:|---:|---:|---|
| DeepSeek，J2（原节选，参照） | 3 | — | — | — | |
| **DeepSeek，L** | **23** | **8** | 15 | **4** | **主张 1：部分成立** |
| Qwen2.5-72B，J2（参照） | 1 | — | — | — | |
| **Qwen2.5-72B，L** | **2** | 1 | 1 | 2 | **主张 3 补标签臂：与主张一致** |
| **Qwen2.5-72B，S** | — | — | **18/18** | 正确定位对照 **1/13** | **主张 3 切片臂：成立** |

**主张 1 为什么是「部分成立」。**
- 预注册的「成立」要同时满足三条：款级检出 ≥ 15/31、不存在的款 ≥ 10/13、误报 ≤ 4/31。
- 第一、第三条满足（23 和 4，误报正好在线上），第二条不满足（8/13）。
- 推翻门槛（≤ 5/31 或误报 > 7/31）没有触发。
- 授权里写的预期（≥ 15/31、误报 ≤ 4/31）达到了。但判定以预注册门槛为准，所以记为部分成立。

**逐条配对（与信息对等运行同条同裁判比）。**
- DeepSeek，L 对 J2：
  - 新检出 20 条；
  - 丢失 1 条（`item_existing-S26-I2`，项级）；
  - 新误报 2 条（`control-S32`、`control_pinpoint-S41`）；
  - 没有误报减少。
- Qwen2.5-72B，L 对 J2：新检出 1 条（`paragraph_existing-S41-P1`），其余不变。
- Qwen2.5-72B，S 对 J1、J2：都是新检出 18 条，丢失和新误报都是 0。
- 剔除 S26 全部变体后复算，三个判定都不变。

**DeepSeek 在 L 下漏掉的 8 条。**
- 不存在的款：S07、S19、S26、S28、S49；同条另一款：S19-P1、S19-P2、S50-P1。
- 8 条的完整理由逐条核过：8 条的理由和引文里都写出了正确的款，即材料里记录的出处款号。
  - **4 条明确写出所引款号不对**，仍判 `supported`：`paragraph_absent-S07`、`paragraph_absent-S28`、`paragraph_existing-S19-P1`、`paragraph_absent-S19`。例如「仅将『第五条第三款』误写为『第五条第五款』，但核心权利内容得到上下文支持」。
  - **另 4 条在理由中写出了正确的款号，但未提及陈述所引的款号、也未指认不符**，直接写「与待核查陈述一致」：`paragraph_absent-S49`、`paragraph_existing-S50-P1`、`paragraph_existing-S19-P2`、`paragraph_absent-S26`。
  - 有了标签以后，引用原文那一行时标签就跟着带出来了。所以「写出正确的款」只说明找到了出处，不说明拿所引款号去比过。
- 【推断】8 条漏判都不在定位这一步。
  - 前 4 条明确看出了不符，没算检出，是因为裁判提示没有规定「定位错、内容对」怎么判，裁判按「核心内容受支持」判了支持。
  - 后 4 条定位同样正确，只是没有指认不符。
  - 这两点都没有单独检验。
- 对照：用关键词粗筛（不符 / 误写 / 有误 / 实际位于 / 序号等），J2 漏掉的 28 条里有 5 条理由写到了款号不对。J2 这个数没有逐条核过。

**误报。**
- `control-S36` 和 `control_pinpoint-S36` 在 J2 下已经误报。陈述只说「包括人民币存款」，原文是「人民币存款和外币存款」，裁判判为遗漏。
- `control_pinpoint-S41`：理由是陈述没覆盖该款全部内容。
- `control-S32`：「…不适用第二条关于投保存款保险的要求」，裁判以「忽略了另有安排的除外」判 `contradicted`。这类陈述里，条号是「不适用」的对象，不是内容出处。这里只记录，不作判定。

## 这说明什么，不说明什么

- 【事实】只加标签、其余逐字节不变，DeepSeek 的款级检出从 3/31 变为 23/31，Qwen2.5-72B 从 1/31 变为 2/31。
- 【事实】同样是 Qwen2.5-72B，上下文换成所引款的切片后，「同条另一款」18/18 检出，正确定位对照误报 1/13；原节选下是 0/18 和 1/13。
- 【推断】DeepSeek 原节选下漏判，主要是因为节选里的款没有可对照的字面标签，不是因为它不比对定位。
  - Qwen2.5-72B 有了标签也不比对定位；但只要给它的就是所引那一款，它会比对内容。
  - 这与主张 1、3 的说法一致。
- 不说明的：
  - **切片条件把「定位」替裁判做掉了。** S 的 18/18 说明 Qwen2.5-72B 会比对给它的文本和陈述，不说明它会找款。上下文变短、干扰变少这一解释，也没有和「只做内容比对」分开。
  - **规则对照不变。** 规则 30/31、[词面基线](../20261022-lexical-baseline/README.md) 31/31 都不依赖标签。本实验不比较规则和裁判，只看裁判在什么输入下会核款号。
  - **其他限制。** 单一法规、共享底稿、单次运行、温度 0，不给区间，只报条数。误报 4/31 正好在门槛线上，再跑一次可能落到线外。
  - DeepSeek 在 L 下漏判的 8 条，理由逐条核过；其余记录（包括 J2 的「5 条」）没有逐条复核。

## 文件与离线复算

- `prep/`：运行前的离线准备，包括 `package.json`、`labeled.txt`（补标签后的节选）、`slices.json`、`estimates.json`（费用预估）和 `authorization.template.json`。
- `run/`：付费运行归档：
  - `authorization.json`：授权，绑定包、配置、提示、补标签节选、切片和工具文件的哈希；
  - `events.jsonl`、`records.json`、`manifest.json`、`schedule.json`、`prompt.txt`；
  - `inputs/`、`sources/`：运行时的输入与工具源码副本；
  - `SHA256SUMS.txt`。
- `analysis/`、`analysis-replay/`：两次离线分析，`analysis.json` 逐字节一致。
- `run.stdout.txt`：运行终端输出（运行时 stderr 为空，未归档）。
- 实现：`tools/competition/statute_labeled.py`；测试：`tests/test_statute_labeled.py`。
- 顶层 `SHA256SUMS.txt` 覆盖本目录全部文件。

复算分析（不发请求，输出目录必须是新的空目录）：

```bash
python tools/competition/statute_labeled.py analyze --run docs/competition/statute-check/20261022-labeled/run --output <新的空目录>
```

`analyze` 会先核对归档里的工具源码与当前源码逐字节一致，再按事件逐条重建记录、计费与停止原因，任何一项不符即停止。
