# 法条结构核对：条、款、项引用与数额期限

**结论：** 用法规原文还原条、款、项结构后，逐句核对回答里的条号归属、数额期限与情态词。四次已归档运行的 100 个回答中只检出 1 个，即 10-14 F04；同次运行的逐句核对把其中一句错误判为有依据。在 42 条注入陈述上，规则检出 29 条错误中的 24 条，13 条对照无误报（离线口径、无裁判对比）。

2026-10-21 又把同一批陈述交给两个通用裁判（裁判只读问题、陈述与检索片段，规则读完整节选），按运行前确认的口径分三组对比：内容类 8 条，规则在它覆盖的两类内容错误上检出 6/6，不在覆盖范围的「否定改肯定」2 条由裁判兜底，与任一裁判合用时 8/8；条号类 16 条，规则检出 14 条，与 DeepSeek 持平，Qwen2.5-72B 只检出 4 条；「应当」改「可以」5 条作为口径依赖项单列。规则零误报，两个裁判各误报 1 条。两套口径用的是同一份规则结果（24 = 6 + 14 + 4），差别只在是否分组、是否和裁判对比，见下文「与通用裁判比较」。

**款项定位与信息对等（2026-10-21、10-22）。** 另一批 66 条款、项定位材料上，31 条款级错误规则检出 30 条；两个裁判原提示下各检出 1 条，换上与规则相同的完整节选后为 3 条与 1 条，信息不对等不是裁判漏检的主因。这些差距不能读成规则判断更强：两批注入都只改条号或款号、内容一字不动，事后写的词面最近邻（与规则同一个覆盖率函数，不设阈值、不用交叉引用豁免）在条号类 16 条与款级 31 条上全部分开，两批对照均零误报，见下文「词面基线」。规则领先之处说明的是原提示下的通用裁判没有去核条号或款号，而规则核；上述10-22实验尚未检验改写内容，新增检查见下段。

**改写材料与强简单基线（2026-10-23，[12条差距复核](20261023-stage3-baselines/README.md)）。** 按运行前修订登记纳入16个单元的T2共72条（错误40、正确对照32）：原规则R检出27/40、误报0/32；词面基线X与并集RX均检出39/40、误报1/32，RX逐条等于X。12条差距中，9条是R没有项间内容归属比较，3条未达到原判定条件；其中一条X虽检出错引，却回指了错误的项，检出不等于定位正确。

## 自资料离线诊断

[`scripts/statute_diagnostic.py`](../../../scripts/statute_diagnostic.py) 可在不安装评测库、不使用密钥的条件下诊断自己的资料与回答。复制并填写[构造样例](../../../examples/statute_check/constructed-request.json)，运行：

```powershell
python -I -S -B -X utf8 scripts/statute_diagnostic.py --input examples/statute_check/constructed-request.json --json
```

请求文件的相对路径按当前工作目录解析；工具也可从仓库外调用。公开[契约](../../../schemas/statute-diagnostic.v1.schema.json)中的 `$defs.request`、`$defs.report` 分别定义输入与输出。`engine` 默认为 `base`，显式设为 `extended` 时并列保留原始结果、项级发现和回指。

- **输入边界：**须声明 `sourceFormat: "article-lines-v1"`。条标题与第一款正文同一行；每个物理行是一款，项以「（一）」等开头另起一行，空行结束条。条号范围为1–999。前言、来源附注、段内换行和其他排版需先由资料提供者整理并确认，工具不自动解析或补标签；机械检查不能证明法律语义上的分款正确。
- **段内硬换行不会触发复核，而是被当作新的一款。** 折出来的下半段若恰好构成答案主张的内容，引用原文中不存在的款会被判为通过（exit 0、`no_error_found`）；`structureCheck.status` 恒为 `not_provided`、`expectedUnits` 恒为 `null`，`unparsedLines` 与 `diagnostics` 在这类输入下也为空，输出里没有线索提示排版被误读。已用同一句回答、只改源文折点做过对照：折在「，」后放行，折在句中则报 `MISATTRIBUTED` 并拦截。从 PDF 复制的法规须先整理成每行一款，再作为输入。
- **不可见字符：**`source`、`answer`、`question`、`contexts` 或结构参照正文中出现 Unicode 格式字符（Cf 类，如 U+200B、U+2060、U+FEFF、U+00AD）时，返回 `review`（退出2），诊断码 `INVISIBLE_FORMAT_CHARACTER`，写明字段、首次出现的行列、码位与次数，不自动删除。这类字符常随 Word 粘贴带入，会让条款号匹配失败：修复前，回答把「第三款」写成中间夹 U+2060 时，原本的错引被报成 `no_error_found`。请求文件开头的 UTF-8 BOM 照常去掉，不在此列。
- **必要资料：**`source` 是原文，`contexts` 是本题实际检索片段，`answer` 是待查回答。`question` 缺省时为空，不从回答中补题设。请求最多1 MiB；现有规则没有独立运行时限保证。
- **输出状态：**`findings`（退出1）为检出规则错误；`no_error_found`（退出0）仅为未检出；`invalid_input` 或 `review`（退出2）表示未完成有效核查，`flagged=null`。后两者不生成规则结果。原规则输出不改写，部分或未定回指不算完整定位。
- **记录边界：**输出含原始输入摘要、代码摘要和Python版本，不是安全签名或法律正确性证明。样例是构造材料，故意引用不存在的第三款；退出1是预期结果。新入口的边界测试和构造材料验收不构成新法规泛化准确率。

## 它查什么

基础数额规则汇总 `contexts` 中的数值与单位，不绑定回答所引条款。若提供全文，其他条款出现相同数额也可能不触发数额提示，需回到所引条文核对条件、主体与期限；见 [O 的使用反馈](../external-use-20261029/confirmation-feedback.md)。

RAG 回答法规问题时，常见的错误不是整句编造，而是细节：把内容归到另一条、引用资料里没有的条号、改了期限或单位、把「应当」说成「可以」。通用的忠实度裁判按句子判断「资料能否推出」，不专门核对条款结构；检索片段在切块时又常常丢掉条号标题，例如资料里只剩「（四）经国务院批准的其他情形。存款保险基金管理机构应当……7个工作日内足额偿付存款」，看不出这是第十九条第二款。

[`backend/core/statute_check.py`](../../../backend/core/statute_check.py) 分三步：

1. **还原结构。** 把法规原文（RAG 应用索引的文件，本项目为 [`scenarios/deposit_insurance.txt`](../../../scenarios/deposit_insurance.txt)）按「第N条」切条，条内每行一款，「（一）」开头的行是项。
2. **给片段补条号。** 每个检索片段按逐字包含对应到条款，没有标题的片段也能知道自己属于哪一款。
3. **逐句核对。** 规则如下，只有 error 级算「检出」：

| 规则 | 级别 | 含义 |
|---|---|---|
| ARTICLE_NOT_IN_SOURCE | error | 所引条号不在法规原文中 |
| PROVISION_NOT_IN_SOURCE | error | 所引款、项超出该条的结构 |
| MISATTRIBUTED | error | 内容出自另一条（款），与所引不符 |
| NEGATION_CONTRADICTED | error | 称某条未规定某类数额或期限，但该条有 |
| UNIT_MISMATCH | error | 数值相同而单位与资料不同 |
| QUANTITY_UNSUPPORTED | error | 数额或期限在资料与题目中都找不到 |
| MODAL_SWAP | error | 情态词与资料不同（如应当 / 可以） |
| ARTICLE_NOT_RETRIEVED | warn | 所引条款在原文中，但检索片段里没有它的内容 |
| FROM_QUESTION、DERIVED | info | 数额来自题目，或由题目数额加减得到 |
| RELATIVE_REF | info | 回答自己用了「前款」「本条」，未解析 |

原文里的「前款」「本条」「前条」会先解析成条号。所以回答把「不适用前款规定」写成「不适用第二条第一款」，不算归属错误。

DeepSeek 加核对提示后款级检出升到 22 条，但误报从 2 条升到 7 条；项级 3 条「同款存在的另一项」规则全部漏检，而 DeepSeek 两种提示都检出。配对变化：DeepSeek 新增检出 21 条、丢失 0 条、新增误报 5 条、减少误报 0 条；Qwen2.5-72B 新增检出 2 条（`paragraph_absent-S19`、`item_existing-S26-I1`）、丢失 1 条（`paragraph_absent-S36`），误报无变化。

规则与两种提示下两个裁判任一检出的并集：35 条错误中检出 34 条，唯一漏检 `paragraph_existing-S27-P1`；并集在支持对照上误报 7 条，全部来自裁判。剔除 S26 全部变体后，款级错误剩 30 条，规则检出 29 条、DeepSeek 1→21 条、Qwen2.5-72B 1→1 条、并集 29 条，项级不剩任何材料。

原提示下两个裁判唯一检出的款级错误都是 `paragraph_absent-S36`，同一底稿的 `control-S36` 与 `control_pinpoint-S36` 也都被两者判为不支持，仍是「只说人民币存款被判矛盾」；这条检出不能归因于核对了款号，不外推到其他 ID。

**机制与漏检。** 款级除了核对编号是否存在，还用内容归属比较触发 `MISATTRIBUTED`；项级只核对编号是否存在，不核对项的内容归属。因此，同款项号存在但内容不符的 3 条全部漏检。

`paragraph_existing-S27-P1` 把第二款的偿付期限归到第十九条第一款。按规则的字符二元组覆盖算法，第一款（含其各项）为 `12/32 = 0.375`，第二款为 `31/32 = 0.96875`，差值 `19/32 = 0.59375`；最接近款的覆盖度达到 `ATTRIBUTION_MIN = 0.6`，差值也达到 `ATTRIBUTION_GAP = 0.25`。但第二款原文含「前款」，`_mentions` 将其解析为 `(19, 1)`，命中所引第一款，令 `(article, paragraph) not in mentioned` 为假，豁免了这次归属错误；归档结果为 `flagged=false`、error 代码为空。不是覆盖度不足，也不是不存在款号。具体复算代码见归档说明。

**裁判漏检时写了什么（2026-10-22，离线）。** 原提示下，两个裁判在 31 条款级错误上共漏检 60 次。按理由文字可分三类：32 次理由里没有出现任何款号；20 次复述了陈述中那个错误的款号；另有 8 次写出了内容真正所在的款号，仍判「支持」，其中 Qwen2.5-72B 6 次、DeepSeek 2 次，写法都是「第X条第Y款」。换成加核对提示后，Qwen2.5-72B 仍有 8 次这种情况。可见裁判有时已经找到了正确出处，却没有拿它去对照陈述所引的款号。这一分类只是对理由文字的表层匹配，口径是看过理由之后才定的，不代表裁判的内部推理。逐次结果与复算命令见 [理由分类归档](20261022-pinpoint-reasons/README.md)。

**事后补查：项级归属与正确位置回指（2026-10-22，离线）。** 针对上面 3 条项级漏检，另写了一个扩展模块 `backend/core/statute_locate.py`，在所引款内逐项比较内容归属，阈值沿用原规则，原规则文件一字未改。结果仍是 1/4。S26 的陈述同时复述了第十九条第一款的总领句和第三项，第三项正文只覆盖其中 16/45 的字符二元组，达不到 0.6。这个缺口照实保留，没有为凑数调整阈值或拼入总领句。

扩展还会为每条引用错误指出内容实际所在的条、款、项。已检出的 31 条错误中，28 条指回正确位置，0 条指错，3 条无法确定（`paragraph_absent-S28`、`paragraph_absent-S26`、`item_absent-S26`）。在 10-21 正式运行的 42 条材料上，扩展没有新增任何标记。这些都是看过结果之后、在同一批材料上做的检验，不能当作独立验证；预注册结果仍以上文为准。详见 [事后补查归档](20261022-posthoc-locate/README.md)。

**边界。** 这是定向合成扰动，只涉及单一法规节选，多条变体共用底稿，不能推广总体效果。项级仅有 S26 一份底稿，且其三人历史标注并不一致：V/A 为「支持」，B 为「无法判断」；作者此次确认标签不抹去该历史分歧。规则读取完整节选，裁判只读原检索片段，信息条件不同，不是严格等信息比较。单次运行、不重试，裁判重判可能波动。DeepSeek 请求名为 `deepseek-chat`、实际返回 `deepseek-flash`；Qwen 为 `Qwen/Qwen2.5-72B-Instruct`。运行停止原因为 `completed`，按授权单价估算 ¥0.64859010，不是账单（`actualBillCny=null`）；授权预算 ¥2，请求前预留计费，到上限即停。授权原文、停止规则、逐条响应与离线复算命令见 [运行归档](20261021-pinpoint-run/README.md)。

## 词面基线：注入材料本来就分得开（2026-10-22，离线）

两批注入都只改条号或款号，内容一字不动。为检查这些材料在词面上是否本来就可分，事后写了一个不设阈值的词面最近邻：只看陈述里的第一个条号引用，所引单元不在节选中即标记；否则在同级单元之间比较规则自带的覆盖率函数 `_coverage`，别的单元覆盖率更高即标记。不设最小覆盖率、不设差值、不用「前款」交叉引用豁免。

| 材料 | 分组 | 条数 | 规则 | 词面基线 |
|---|---|---:|---:|---:|
| 款项定位（66 条） | 款级错误 | 31 | 30 | 31 |
| | 支持对照（误报） | 31 | 0 | 0 |
| 正式运行（42 条） | 条号类错误 | 16 | 14 | 16 |
| | 对照（误报） | 13 | 0 | 0 |

只有基线检出的 3 条里，`paragraph_existing-S27-P1` 与 `PS-S27` 是规则的「前款」豁免所致，`AS-S32` 是条号作「不适用」对象的写法，基线只是看出内容更像别的条。项级 3/3 不算可分的证据：S26 最佳项覆盖率只有 16/45，基线能分开只因为不设最低覆盖率。

所以规则对裁判的领先，说明的是原提示下的通用裁判没有去核条号或款号，而规则核；不说明规则在语义上判断得更好。基线是看过结果后写的；该10-22归档尚未检验改写内容。10-23新增改写材料检查见上文和[差距复核](20261023-stage3-baselines/README.md)。详见 [词面基线归档](20261022-lexical-baseline/README.md)。

## 与同类研究的关系

同类研究指出，模型能认出引用的主题，却核不准具体的款项和定位。本规则针对这一层结构与字面细节，在本次注入的 13 条对照上零误报。

- [Is this Citation on Point?](https://arxiv.org/abs/2608.12571)：受控扰动下，14 种模型配置对换案例的检出为 93–100%，对同一案例只改页码定位的检出在判决书上为 37–61%、诉状上为 52–83%；漏检时会凭主题相近接受引用，提示核对定位可提高召回，也会增加误报。本项目早先「加错误款号」2 条，两个裁判都没检出，规则检出 1 条；本次款级错误 31 条，规则检出 30 条，DeepSeek 加核对提示后从 1 条升到 22 条，但支持对照误报从 2 条升到 7 条，Qwen2.5-72B 两种提示各检出 1 条，见 [款项定位运行归档](20261021-pinpoint-run/README.md)。论文观察到模型漏检时会凭主题相近接受引用；本项目原提示下 60 次漏检中，有 8 次裁判在理由里写出了正确款号，仍判「支持」，现象相近，见 [理由分类归档](20261022-pinpoint-reasons/README.md)。涉及的也是具体定位核对，只能说方向相同。
- [SearchFireSafety](https://arxiv.org/abs/2604.06173)：条文证据分散在层级结构中，普通检索拿不全，作者称之为 statutory retrieval gap；上下文不完整时模型会编造。本项目已有检索片段丢掉条号标题的情况，规则从法规原文还原条、款、项，再给片段补条号。
- [HalluGraph](https://arxiv.org/abs/2512.01659)：基于语义相似度的幻觉检测容易放过当事人、日期、条款等实体替换。本规则逐句核对条号归属、数额期限与单位，补查这些字面细节，但不覆盖一般实体或语义错误。
- [PARCEL](https://arxiv.org/abs/2610.10971)：判断法律陈述是否有依据时，「缺少依据」比「直接矛盾」更难检出。本项目 C-S36 被两个裁判因未提外币存款而判为矛盾，是把不完整当成矛盾；这说明核对时也要分清两者，不能把该例当作对论文结论的验证。
- [FiscalQA Pro](https://arxiv.org/abs/2608.09393)：采用正则、数值容差等确定性规则评分，不用 LLM 裁判，理由是裁判会继承被测偏差。本项目也用离线规则核对可明确判定的结构与字面，且规则在构造注入集之前定稿；这不意味着规则覆盖了裁判的全部任务。
- [CLaw](https://arxiv.org/abs/2509.21208)、[LegalHalBench](https://arxiv.org/abs/2501.06521)、[CitaLaw](https://arxiv.org/abs/2412.14556)：分别是中文法律条文知识基准、法律问答幻觉基准、法律引用对齐基准，都不是对 RAG 回答做事后核对的工具。本项目做的是回答生成后的条款引用与字面核对，任务位置不同；注入实验只检验规则设计要查的错误类型，不能替代这些基准。

外部数字和本项目数字不能直接比较，样本、语言和任务都不同。早先「加错误款号」只有 2 条；本次另有 31 条款级错误、4 条项级错误，仍是定向扰动且共用底稿。DeepSeek 核对提示增加检出也增加误报，只能说方向相同，不能说结论一致，详见 [本次归档](20261021-pinpoint-run/README.md)。规则只覆盖结构与字面，PARCEL 所说的「缺少依据」本规则不查。

**立法技术上的依据（交叉领域，2026-10-24 查阅）。** 款级引用难核，和立法起草的写法有关。

- **中国：款不编号。** 中国民用航空局《[民航规章立法技术规范](http://www.caac.gov.cn/XXGK/XXGK/GFXWJ/201511/t20151102_8224.html)》（MD-LR-2013-01）写明：
  - 款一般以自然段的形式出现，「不采用序数编码」；
  - 项用（一）（二）等序数；
  - 引用时写作「第X条第X款第X项」。

  所以按款引用时，所引的编号并不出现在条文里，要靠数自然段得出。这与上文复现的结果一致：原节选下，条号引错检出 10/10，款号引错只检出 1/10。条号写在正文里，款号没有。
- **法国：alinéa 也不编号。** Légifrance《[立法技术指南](https://www.legifrance.gouv.fr/contenu/Media/files/autour-de-la-loi/guide-de-legistique/2024_12_05_fiche_3.2.2_division_du_texte.pdf)》第 3.2.2 节（2024-12-05 版）：
  - 现行规则下，另起一行的列举项也算一个 alinéa；旧规则把列举项算作前一个 alinéa 的延续；两种计数在现行法里并存。
  - 指南承认，按 alinéa 引用常常不方便或有歧义，建议在款首加数字或字母。
- **补标签与这条建议做的是同一件事**：把隐含的编号写出来，只是读者从人换成了裁判。所以补标签不是新想法；本项目做的是在裁判上量出它的作用，见上文「补标签干预」与「换一部法规复现」。
- **两地的计数规则不同。** 中国的项不算款，法国现行规则下列举项算 alinéa。本规则按中国惯例，只把以全角「（一）」开头的行算作项；列举项如果用半角括号等写法，会被算成款。
- **边界。**
  - 这是文献上的类比。本项目没有在法国法条或其他法域上运行过，不能说那里的裁判也有同样的盲区。
  - 全国人大常委会法工委《立法技术规范（试行）（一）》的原文这次没有取得，上面引的是民航局的规范。

## 不能说明什么

- **数字只适用于本次注入。** 规则与注入集都由 AI 编写，且规则在构造注入集之前定稿。检出率衡量的是「规则对它设计要查的错误类型查得怎样」，不能当作对一般错误的检出率。
- **真实错误样本只有 1 例。** 100 个回答里规则只检出 F04，它确属错误。其余 99 个没有人工逐题核对过，「未检出」不等于「没有条款错误」。
- **场景单一。** 只在一份法规节选（9 条）上开发和检验。原文格式假设为空行分条、每行一款、「（一）」为项，其他格式需要另写解析。
- **只查结构与字面。** 极性反转、语义改写、条文内容本身是否正确，都不检查。
- **项级内容归属仍是缺口。** 引成同款另一项的 3 条错误，原规则和事后补写的项级比较都没有查出；正确位置回指的 28/31 也是看过结果后在同一批材料上得到的。
- **注入陈述不是独立样本。** 42 条共用 11 条底稿，不给区间。
- **注入材料已经作者确认，漏检解释没有。** 2026-10-21 作者在付费运行前逐条确认了 42 条材料并定下口径；上面的漏检解释由 AI 写出，未经作者逐条确认。
- **裁判对比规模小。** 只有两个裁判，各跑一次，裁判自身的重判波动没有测；法规是节选，「改为节选中没有的条」只说明不被所给材料支持。
