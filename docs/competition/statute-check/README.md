# 法条结构核对：条、款、项引用与数额期限

**结论：** 用法规原文还原条、款、项结构后，逐句核对回答里的条号归属、数额期限与情态词。四次已归档运行的 100 个回答中只检出 1 个，即 10-14 F04；同次运行的逐句核对把其中一句错误判为有依据。在 42 条注入陈述上，规则检出 29 条错误中的 24 条，13 条对照无误报。通用裁判在同一批陈述上能检出多少，需要一次付费运行，**尚未运行，等待单独授权**。

本功能是独立的诊断通道，不进入 `pos_faithfulness`，不改门禁口径；已记录的 FAIL（0.7375、0.765 等）都不变。

## 它查什么

RAG 回答法规问题时，常见的错误不是整句编造，而是细节：把内容归到另一条、引用资料里没有的条号、改了期限或单位、把「应当」说成「可以」。通用的忠实度裁判按句子判断「资料能否推出」，不专门核对条款结构；检索片段在切块时又常常丢掉条号标题，例如资料里只剩「（四）经国务院批准的其他情形。存款保险基金管理机构应当……7个工作日内足额偿付存款」，看不出这是第十九条第二款。

[`backend/core/statute_check.py`](../../../backend/core/statute_check.py) 分三步：

1. **还原结构。** 把法规原文（RAG 应用索引的文件，本项目为 [`scenarios/deposit_insurance.txt`](../../../scenarios/deposit_insurance.txt)）按「第N条」切条，条内每行一款，「（一）」开头的行是项。
2. **给片段补条号。** 每个检索片段按逐字包含对应到条款，没有标题的片段也能知道自己属于哪一款。
3. **逐句核对。** 规则如下，只有 error 级算「检出」：

| 规则 | 级别 | 含义 |
|---|---|---|
| ARTICLE_NOT_IN_SOURCE | error | 所引条号不在法规原文中 |
| PROVISION_NOT_IN_SOURCE | error | 所引款、项超出该条的结构 |
| MISATTRIBUTED | error | 内容出自另一条（款），与所引不符 |
| NEGATION_CONTRADICTED | error | 称某条未规定某类数额或期限，但该条有 |
| UNIT_MISMATCH | error | 数值相同而单位与资料不同 |
| QUANTITY_UNSUPPORTED | error | 数额或期限在资料与题目中都找不到 |
| MODAL_SWAP | error | 情态词与资料不同（如应当 / 可以） |
| ARTICLE_NOT_RETRIEVED | warn | 所引条款在原文中，但检索片段里没有它的内容 |
| FROM_QUESTION、DERIVED | info | 数额来自题目，或由题目数额加减得到 |
| RELATIVE_REF | info | 回答自己用了「前款」「本条」，未解析 |

原文里的「前款」「本条」「前条」会先解析成条号。所以回答把「不适用前款规定」写成「不适用第二条第一款」，不算归属错误。

## 已归档的 100 个回答

四次运行各 25 题：10-05 DeepSeek 自评、10-14 Qwen 裁判重跑、10-14 自写示例应用、10-21 AnythingLLM。

| 运行 | 检出 |
|---|---|
| 10-05 DeepSeek | 无 |
| 10-14 Qwen 裁判 | **F04** |
| 10-14 示例应用 | 无 |
| 10-21 AnythingLLM | 无 |

**F04（10-14）。** 题目说「第十九条要求 7 个自然日内偿付」，回答称「第十九条本身并未规定偿付时限」，又把「7个工作日」归到「第十八条」。

- 规则检出两处：
  - 第十八条不在节选中（ARTICLE_NOT_IN_SOURCE）；
  - 第十九条第二款就规定了 7 个工作日（NEGATION_CONTRADICTED）。
- 同次运行的逐句核对，把「第十八条」一句判为编造，却把「第十九条本身并未规定偿付时限」判为有依据。它引用的依据是第十九条第一款，而真正规定时限的第二款在另一个没有条号标题的片段里。
- 回答里的「而非 7 个自然日」是在否定题目说法，不算无依据的数额。

**C02（四次运行都有）。** 「合计 51 万元」「超出部分 1 万元」由题目给出的 49 万元、2 万元推算得到，记为 info，不算检出。Ragas 在这几次运行中都扣了分，这是口径问题，不是条款错误。

规则在这 100 个回答上调整过一次：AnythingLLM 的 C01 把「前款」写成了绝对条号，最初被误报为归属错误，于是加了原文相对引用的解析。此后规则定稿，再构造注入集。

## 注入实验

**材料。** 底稿是门禁 52 条陈述中，三位非作者（V、A、B）都判为「支持」、且含条号、数额期限或情态词的 11 条。每条注入只做一处逐字替换，对照组是原陈述，以及加了正确款号的 2 条。

| 类型 | 说明 | 条数 | 规则检出 |
|---|---|---:|---:|
| 对照 | 原陈述 | 11 | 0（无误报） |
| 对照 | 加一个正确的款号 | 2 | 0（无误报） |
| 改条号 | 改为节选中的另一条 | 7 | 6 |
| 改条号 | 改为节选中没有的条 | 7 | 7 |
| 改款号 | 加一个错的款号 | 2 | 1 |
| 改数额 | 数值改变 | 4 | 4 |
| 改单位 | 工作日→日、个月→年 | 2 | 2 |
| 改情态词 | 应当→可以 | 5 | 4 |
| 改极性 | 不适用 / 不属于→肯定 | 2 | 0（不在覆盖范围） |

**漏检的 5 条：**

- 改极性 2 条，本规则不覆盖。
- AS-S32「不适用第四条关于投保存款保险的要求」：条号是「不适用」的对象，不是内容出处，内容归属比较分不出来。
- PS-S27「根据第十九条第一款，……在前款规定情形发生之日起……」：陈述里自带的「前款」被当作对第一款的合法引用，豁免放宽了。
- MD-S27：底稿陈述把原文的「应当依照本条例的规定，在前款……」省略为「应当在前款……」，情态词后面的文字与资料对不上，比对不出替换。

**与通用裁判比较（待运行）。** 同一批 42 条陈述交给两个裁判：

- 裁判：DeepSeek-chat、Qwen2.5-72B；
- 提示词：与 [裁判证据敏感性实验](../judge-sensitivity/README.md) 相同的固定陈述核查提示词；
- 输入：只有问题、陈述与检索片段；
- 规模：共 84 次请求。

工具是 [`statute_injection.py`](../../../tools/competition/statute_injection.py)，流程沿用该实验：材料确认、授权绑定哈希、不重试、预算守卫、原始响应归档。运行前不预测结果；裁判检出多少，就照实写多少。

## 不能说明什么

- **数字只适用于本次注入。** 规则与注入集都由 AI 编写，且规则在构造注入集之前定稿。检出率衡量的是「规则对它设计要查的错误类型查得怎样」，不能当作对一般错误的检出率。
- **真实错误样本只有 1 例。** 100 个回答里规则只检出 F04，它确属错误。其余 99 个没有人工逐题核对过，「未检出」不等于「没有条款错误」。
- **场景单一。** 只在一份法规节选（9 条）上开发和检验。原文格式假设为空行分条、每行一款、「（一）」为项，其他格式需要另写解析。
- **只查结构与字面。** 极性反转、语义改写、条文内容本身是否正确，都不检查。
- **注入陈述不是独立样本。** 42 条共用 11 条底稿，不给区间。
- **作者尚未逐条确认。** 注入材料与漏检解释都还没有经过作者逐条确认。
