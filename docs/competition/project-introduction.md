# 鉴真全域 VeriScope AI 作品介绍

> AI 测试交付与质量门禁平台

材料日期（PDF 导出）：2026-10-09；证据运行日期：2026-10-05。已完成工作与本轮实验的状态分别说明。

## 一、项目背景

AI 应用上线前，「回答是否可信」的判断往往停在一个平均分或肉眼抽查，既难以解释错误出现在哪里，也难以据此判断是否达到发布要求。缺少的是一套**可交付、可复用**的测试结论。

鉴真全域 VeriScope AI 面向 AI 应用（当前以 RAG 问答为测试对象）的测试交付，把测试用例集、检索上下文、模型回答、逐句断言、多模型指标、质量门禁（Quality Gate）与人工复核汇集到中文工作台，把「回答是否可信」变成一条可逐条回查的结论：

> 用例 → 断言 → 门禁 → 报告 → 复核

## 二、创新点

与现有主流方案相比，本项目的差异在于**把指标计算补齐为一条可交付、可复核的测试链路**：

| 现有方案 | 侧重 | 本项目与之的差异 |
|---|---|---|
| Ragas | 指标计算（忠实度、上下文精度等） | 本项目**以 Ragas 为指标层**，向上补齐「逐句断言 → 质量门禁 → 报告交付 → 人工复核」闭环 |
| DeepEval | LLM「单元测试」式断言、偏英文与通用用例 | 本项目面向**中文**，以**证据可回查**为核心，把回答拆成原子陈述并保留判定与检索原文 |
| TruLens | 运行时追踪与可观测（instrumentation） | 本项目聚焦**上线前的测试交付**，输出可归档、可门禁、可复核的测试结论，而非运行时观测 |

具体创新点（均有实现）：

1. **逐句断言 + 证据回查**：把回答拆成原子陈述，逐句给出「有依据／事实错误／无依据编造」的原判定，并与对应检索原文并列呈现。
2. **质量门禁（Quality Gate）**：按正向忠实度与正向上下文精度双阈值（默认各 0.8）判定是否放行，并**保留真实 FAIL**、不隐藏。
3. **负向样本的拒答语义区分**：对文档未提及的问题，模型拒答属正确行为；系统按样本类型区分对待，避免把「正确拒答」误读为缺失或无法评估。
4. **人工复核模块**：人工结论与机器原判定**分列呈现**，核验材料绑定冻结快照版本与 SHA-256，便于追溯。
5. **测试结论可交付**：输出 CSV / HTML / Excel( XLSX ) / PDF 与图表，便于归档与评审。

## 三、技术架构

![鉴真全域 VeriScope AI 技术架构](../images/architecture.png)

| 模块 | 技术与职责 |
|---|---|
| Frontend | React 19、TypeScript、Vite、Apache ECharts；首页与六个工作台视图 |
| Backend | Python、FastAPI；参数与路径校验、同步评测调用、结果序列化 |
| Evaluation Pipeline | LangChain、Chroma、本地 Embedding、Ragas；文档 → 测试集 → 检索与回答 → 指标与溯源 → 门禁与报告 |
| Model Adapter | OpenAI-compatible 适配；DeepSeek、Qwen2.5-7B、GLM-5.2-Fast |
| Compatibility | 保留 CLI 与 Gradio 入口；报告、存储、服务与核心评测在 `backend/` 分层 |

评测链路为：文档 → 测试集 → 检索 → 问答 → 指标 → 溯源 → 门禁 → 报告 → 复核。

## 四、应用场景与实际使用案例

### 应用场景：RAG 应用上线验收

对智能问答、知识库问答等 RAG 应用，在上线前用固定测试集跑一次评测，由质量门禁判定是否放行；未通过时，逐句溯源定位到「哪一句、依据哪段上下文、判定是什么」，便于修复与复评。

### 实际使用案例（仅引用已有运行证据）

- **案例一：25 题单模型正式运行（证据运行日期 2026-10-05）**
  使用《存款保险条例》节选的固定案例集，正向 Faithfulness **0.7375 低于 0.8**，正向 Context Precision 0.9833 达到 0.8 → 原始 Quality Gate **保留 FAIL**。即：**该次评测被门禁拦下**，且完整回答、contexts、指标、Trace、报告与哈希均已归档，可逐条回查失败原因。
- **案例二：历史金融场景旧 CLI 运行**
  正向上下文精度 **0.7778 低于 0.8** → FAIL；该案例与当前演示快照分开保存。

> 两个案例均为**真实运行**：门禁把未达标的评测挡在发布前，逐句溯源给出具体语句与证据。

## 六、技术限制与诚实边界

- **self-Judge**：当前后端会将相应被测模型用于 Ragas 评测与 Trace 判定，存在生成与裁判同源的偏差；人工核验有助于暴露分歧，但作者自审不能替代独立复核。
- **阈值未业务校准**：默认 0.8 尚无业务校准证明；PASS 仅说明指定样本达到保存门槛，不代表所有指标优秀或每条回答正确。
- **无鉴权与访问隔离**：当前服务定位为本地评测与展示，缺少生产所需的访问控制。
- **同步评测**：真实评测采用同步请求，尚无生产所需的完整长任务管理与进度接口。
- **空 Trace 不等于无幻觉**：空 Trace 或缺失指标不能作为无幻觉证明；逐句判定依赖原始溯源记录，不是额外的独立真实性保证。
- **样本范围**：25 题为单一金融材料的固定场景，部分题目共享法条，**不是跨领域 Benchmark、统计独立样本或总体准确率证明**。
- 历史快照还缺少确切的裁判版本、提示词版本与完整环境记录。
