# 项目索引

**一句话**：RAG 应用上线前，逐句核对回答与检索原文，再由门禁决定这批回答能不能放行——错在哪句、修完有没有变好、凭什么放行，都能回查。

下面按四块展开：技术创新、场景落地、开源治理、长期发展。每块回答同样三件事——做到了什么、证据在哪、下一步验证什么。数字、方法和限制写在被指向的那一页，本页只负责指路。

> `docs/competition/` 是历史路径，仓内外已有链接指向这里，没有改名；本页与下列各页讲的是项目本身。

只读一页：[作品介绍](project-introduction.md) —— 定位、能力清单、行业要求对照，以及每条能力对应的证据与边界。

## 01 技术创新

> 这一维看：技术路线、具体增量及与已有方法的对照证据。

**做到了什么**

- **指标层不重造，增量在指标之上。** 五个指标直接复用 Ragas 0.1.21，不改公式、不改权重，便于按固定口径复算。自研的是它上面那层：逐句判定与证据定位、质量门禁、人工核验存档、中文陈述兼容层；对应代码在 `backend/services/trace.py`、`backend/core/gate.py`、`backend/adapters/ragas_compat.py`，可以直接读。
- **发现并补上了一个具体的上游缺口。** Ragas 0.1.21 在 Faithfulness 与 Answer Correctness 里，分句之后只保留以英文句号结尾的句子；中文以「。」结尾，整段回答进不了陈述抽取提示。修正前的 5 题预跑，Faithfulness 缺失 2/5、Trace 空 2/5——那不是模型表现差，是指标根本没拿到输入。`zh-sentence-v1` 只把含中文的非空分句按原顺序送进原提示，纯英文仍走原实现，评分公式、权重和裁判提示都不动；修正后 15 条抽取提示全部带上中文原文，五项指标各 5/5 有效。该兼容层对应本项目固定的 Ragas 0.1.21 路径。
- **把低分定位到具体问题与修复入口。** 同一次运行，只看 Ragas 平均分 0.59，看不出低在哪——9 道低分里有 5 道是本来该拒答的负向题，答对了却按 0 分计。分开正负样本后正向忠实度 0.7375，门禁判 FAIL；到阈值的缺口只有 0.0625，而 4 道错误前提题单独拉低 0.2，超过缺口的三倍。这几道题的检索召回都是 1.0，所以该修生成，不是修检索。
- **把门禁自己当被检查对象。** 本项目对门禁提四问——能不能复算、换裁判会不会变、裁判是否依据证据、结论有多确定——各自给出实验记录与复算入口。相关工具的功能定位比较见[作品介绍](project-introduction.md#二创新点)。
- **主动把对照方做强。** 法条结构核对不跟弱基线比：强化裁判提示、给裁判相同的完整节选、加词面最近邻基线、换一部法规的 AI 改写材料再比；检出、误报、定位错误一并报告。

| 结论 | 证据 | 边界 |
|---|---|---|
| 门禁结论可逐题复算，20 / 20 道正向题与归档一致 | [门禁可信度四问](gate-credibility.md) | 全部来自同一次 25 题运行 |
| 门禁代码本身有测试：42 个变异抓住 39 个 | [门禁代码自检](gate-self-check/) | 存活 3 个不影响裁决；只说测试能发现这些改动 |
| 受控注入材料上款级检出 30/31、支持对照误报 0/31 | [法条结构核对](statute-check/) | 规则覆盖面有限，检出不等于正确定位 |
| 换裁判重跑，PASS 变回 FAIL（0.7992），两次结论都保留 | [独立裁判复核](evidence/20261014T125415Z-full-a5002d4f/) | 回答重新生成，不能把变化全归因于裁判 |
| 与 RAGChecker 所用核查器同条件对照（同 20 题、52 条陈述、同一模型，各 3 轮）：人工确定集 46 条上一致本项目 45/44/45、RefChecker 43/43/43；差异全在仅 6 条的不支持类（6/6 对 3/3），按预登记为「无可证优势」 | [RefChecker 对照](judge-comparison/20261030-refchecker/README.md) | 对照的是其整句核查路径，非默认三元组配置；RefChecker 漏判的 3 条出自同一道题，去掉题面后 2 条改判，原因待验证；证据等级 E |

**下一步验证**：在新的独立材料上复查规则与词面基线的检出、误报和定位。已有强简单基线比较中，换一部法规的改写材料后，规则检出 27/40、误报 0/32，词面基线检出 39/40、误报 1/32；12 条差距里 9 条源于原规则没有项间内容归属比较，其余 3 条是未达到保守判定条件，而基线那 39 条里还有一条检出正确、回指位置错误。另外，词面基线、事后补查、补标签这三项都是看过结果之后在同一批材料上做的，不能当独立验证。

## 02 场景落地

> 这一维看：是否可部署、可运行、可测试；需求是否真实；方案是否适配场景；验证是否来自真实或仿真环境。

**做到了什么**

- **三种形态都有现成入口。** 独立质检平台（Docker Compose 到内网）、嵌入现有系统（HTTP 接口 / Python 函数 / `--generator-endpoint`）、CI 门禁（GitHub Action，别的仓库加一步 `uses: 4444wjt/RAG_Evaluation_Demo@master`）。
- **可运行，而且不要求你先有密钥。** 在线演示站免登录、不调用模型；仓库内的无密钥快照可本地打开；法条诊断 CLI 已单独打包发布，Windows Python 3.11 / 3.12 的 wheel 安装验证过；6 个零依赖脚本不装评测库就能跑。
- **可测试，两条命令当场复算。** 一条复算门禁裁决，一条校验文件没被改过，见[复算入口](#复算入口)。
- **需求有条款对照与实测反馈。** 作品介绍的行业要求对照列出六条要求、对应能力与证据；外部实测还发现：银行公开问答 11 题门禁 PASS，但 6 道负向题全部给出了节选外内容 —— 只看正向题的门禁，拦不住不拒答的应用。
- **适配的是「答错要担责」的场景。** 拦的是上线前和每次改动后的版本，只查回答与资料是否一致，所以面向资料本身权威、答错代价高、需要留痕、要求私有化的行业：银行 / 保险条款问答、政务咨询、央国企制度问答。反过来，新闻资讯与联网搜索、营销与闲聊、投资建议与医疗诊断、线上逐条实时拦截，明确不做。
- **验证来自真实环境。** 6 个运行归档里有 3 次 25 题正式运行、2 次 5 题预跑，另有 1 次不调用模型的 PDF 解析检查；每批模型调用单独授权，原始结果连哈希一起归档。外部接入实测过自写示例、AnythingLLM 源码构建实例、银行公开问答三种；还有 24 道未参与调试的留出题，和两个带人工标注的公开中文基准（ANAH、RGB）。
- **外部操作者带自选资料使用。** 同一操作者 O 的 [10-27 远程操作作者电脑](external-repro-20261027/README.md)与 [10-29 本人电脑验收](external-use-20261029/README.md)已有记录；后者为 1 项法规规则验收、3 条构造陈述与 3 次请求，原退出码 0/0/1，预设引用偏离发现 1/2、未发现 1/2。

| 形态 | 怎么接 | 边界 |
|---|---|---|
| 独立质检平台 | 本机工作台，或 [Docker Compose 部署](../DEPLOYMENT.md) | 无鉴权，评测是同步请求 |
| 嵌入现有系统 | HTTP 接口 / Python 函数 / `--generator-endpoint`；任何 OpenAI 兼容接口登记即可参评 | 密钥只写本机 `.env` |
| CI 门禁 | [GitHub Action](../../action.yml)，归档结果离线重放 | 只拦确定退步；阈值未经业务校准 |
| 外部应用端到端 | `veriscope.e2e.v1`，只发题号与问题 | 应用须自己返回回答与 contexts |

**下一步验证**：补充非金融场景的端到端门禁与更多外部操作者。现有正式运行的 25 题来自同一份金融材料，按同材料问题统计；在线演示依赖试用期云资源，仓库与静态备用站保留复查入口。

## 03 开源治理

> 这一维看：开源协议与依赖是否合规；贡献机制、文档与 Issue/PR 是否清晰；新项目看规划，成熟项目看运营。

**项目阶段**：单人维护的新项目，治理流程于 2026-10-26 写入仓库；已有同一外部操作者 O 在两个日期的使用与反馈记录，贡献流程、上游合并和发布记录分别列证。

**做到了什么**

- **协议干净。** 自有代码 Apache-2.0，第三方依赖适用各自许可；许可从 Commons Clause 转到 Apache-2.0 的范围与理由单独成文。
- **依赖不为了变绿而放宽。** pypdf 钉在 6.19.0，这个版本把预定义 CMap `UniGB-UTF16-H/V` 按 GB18030 解，缺 ToUnicode 的中文 PDF 会解出乱码，测试夹具在它下面判 FAIL。项目没有升依赖、没有改阈值来把这条变绿，而是把修复提交到上游；本地判定暂时保持不变，原因写在根目录 README。
- **贡献与治理写成了文件。** [CONTRIBUTING](../../CONTRIBUTING.md)、PR 模板、两个 Issue 模板、[SECURITY](../../SECURITY.md)、[CODE_OF_CONDUCT](../../CODE_OF_CONDUCT.md)、[GOVERNANCE](../../GOVERNANCE.md)——维护者增补、决策记录、分支与发布、写入授权、维护连续性各成一节。
- **上游有实际合并记录。** 作者 `4444wjt` 向 pypdf 提交的两项修复都已合并：`UniGB-UTF16-H/V` 按 UTF-16BE 解码；奇数长度、末字节小于 `0x80` 的 UTF-16BE 字符串在解码回退时不再抛错。前者随 6.21.2 发布。
- **CI 与自动化。** 6 个 workflow（`ci` / `codeql` / `mutation` / `pages` / `quality-gate-example` / `scorecard`）加 dependabot；合并前要求 CI 全绿，同时写明「CI 通过只证明该提交的自动检查结果」。
- **真实反馈形成文档回应。** O 提出数额是否按所引条款核对，并建议明确范围；[反馈与确认摘要](external-use-20261029/confirmation-feedback.md)说明当前规则按 contexts 汇总数额、本次提供全文，保留 002 未发现的原结果。

## 复算入口

三样东西不需要密钥，可以当场复算：门禁回放 `scripts/gate_replay.py`、哈希清单 `SHA256SUMS.txt`、离线分析表 `analysis.json`。回到仓库根目录：

```bash
python scripts/gate_replay.py docs/competition/evidence/20261005T144504Z-full-39511424/api-response.json
cd docs/competition/evidence/20261005T144504Z-full-39511424 && tr -d '\r' < SHA256SUMS.txt | sha256sum -c --ignore-missing -
```

前者复算门禁裁决，退出码含义、`--baseline` 与 JUnit 参数见[门禁回放](../gate-replay.md)。

后者两个选项各有原因：`--ignore-missing` 跳过清单里未公开的中间产物（服务器日志、报告图表），`tr -d '\r'` 兼容 Windows 检出的行尾——`SHA256SUMS.txt` 未钉 LF，不处理会让整份清单报「找不到文件」。哈希证明的是文件没被改过，不是内容正确。

历史 FAIL 不回填、冻结快照不改；新写出的分析都标「AI 辅助分析、待人工确认」。
