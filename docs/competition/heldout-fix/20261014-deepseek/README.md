# 修复验证（留出题）：错误前提纠正在 24 道新题上的前后对照（2026-10-14）

**结论：** 在没参与调试的新题上，修复同样有效，没有发现副作用。

- 错误前提题：**9/14 → 14/14** 通过。5 道题从拒答变为依据资料纠正，没有一道变差。
- 正确前提题：4/5 → 5/5。修复后没有把正确说法「纠正」成错的。
- 资料没有答案的题：5/5 → 5/5。全部仍正确拒答。
- 预先固定的配对符号检验：错误前提题上 5 道改善、0 道变差，双侧 `p = 0.0625`，**未达到 0.05**。题量小，这一结果只能算方向一致的证据，不能算统计上显著。

## 为什么要做这一轮

[10-05 正式运行](../../evidence/20261005T144504Z-full-39511424/README.md) 发现错误前提题被直接拒答，提交 `b90a14c` 在问答提示词中加了一句：
> 如果问题中的说法或前提与参考资料不一致，请依据参考资料指出并纠正，不要拒答。

[修复后重跑](../../evidence/20261014T073859Z-full-1c6f091f/README.md) 门禁从 FAIL 变为 PASS。但那是在**发现问题的同一批 25 题**上验证的，不能排除修复只对这批题有效。这一轮另出 24 道新题，检验修复能否推广。

## 做法

- **题目**：[`scenarios/heldout_fp/`](../../../../scenarios/heldout_fp/README.md)，两份法规节选共 24 题，分为错误前提 14、正确前提 5、资料无答案 5。
  - 题目由 AI 辅助起草，作者 Kk 于 2026-10-14 逐题核对后确认。BN01 按作者要求替换过一次，替换后的题目也经作者确认。
  - 题目在运行前固定，哈希 `c413e54e…`，记录在 `package.json`。
- **两组只差一句**：修复后组用当前问答提示；修复前组用同一段生产代码拼出提示，发出前去掉那一句。离线测试 [`tests/test_heldout_fix.py`](../../../../tests/test_heldout_fix.py) 核对过，修复前组的提示与修复前的提示逐字一致。
- **两组看到的资料相同**：运行前用平台相同的切分、Embedding 和 Top-K 检索出每题资料，固定在 `package.json` 里。19 道有答案的题全部检到了原文依据。
- **判定标准在运行前固定**，写在 `package.json` 的 `outcomeRules` 里：
  - 错误前提、正确前提：没有拒答，且逐句核对没有与资料矛盾（`fact_error`）的陈述，算通过。
  - 资料无答案：拒答算通过。
  - 两组按题配对，只看结果不同的题，用精确符号检验（双侧）。
- **模型**：两组都是 `deepseek-chat`，温度 0，接口返回的模型名都是 `deepseek-flash`。逐句核对用的也是同一个模型。
- **运行工具**：[`tools/competition/heldout_fix.py`](../../../../tools/competition/heldout_fix.py)。
  - 授权绑定题目、材料包和运行代码的哈希，代码有改动就拒绝运行。
  - 设预算上限和请求数上限，不重试。

**次要指标：作答题中全部陈述都有依据的题数。**
- 错误前提题：修复前 9/14，修复后 13/14。
- 修复后唯一的例外是 AF06。答案里「不是由财政拨款形成」一句被判为「资料中找不到依据」（`fabrication`）。这句是在否定题目的错误前提，资料确实没有直接写这句话，这是逐句核对对「否定陈述」的判定口径所致，按规则照实计入。

**一个观察：** 修复前的拒答集中在存款保险资料上，6 道错误前提题拒答了 4 道；政府信息公开资料只拒答了 1 道。同一模型在不同资料上的拒答倾向差别很大。原因本次没有分析。

## 不能说明什么

- **题量小。** 错误前提题上只有 5 道结果不同，符号检验 `p = 0.0625`，未达到 0.05。
- **只有一次运行、一个模型。** 没有验证 Qwen、GLM 等其他模型；温度 0 下重跑的结果也可能略有不同。
- **一半的题与调试用的资料相同。** 存款保险节选就是发现问题时用的那份资料；政府信息公开节选没参与这次调试。不过从结果看，两份资料上都没有变差。
- **判定靠自动逐句核对和拒答识别，没有人工复核每个回答。** 两组的回答原文都在 `items.json` 中，可以逐条查看。
- 只检验了新增这一句的效果，没有比较其他写法；不计算 Ragas 指标，也不给门禁结论。
- **只用于检验修复。** 本题集是在修复之后设计的，以后如果据此再调提示词，这批题也就不再是留出题了。

运行代码的哈希记录在 `authorization.json` 的 `toolSha256` 里，是 Windows 工作区的字节。其中 `backend/services/answering.py` 在 Windows 工作区为 CRLF，记录值是 `efcb4f16…`；按 LF 检出（如 Linux）时的哈希是 `3cbe9c87…`，两者内容相同。其余文件都是 LF。

## 文件

| 文件 | 内容 |
|---|---|
| `summary.json` | 分组结果、配对比较、符号检验、用量 |
| `items.json` | 两组逐题的回答原文、拒答判定、逐句核对结果与最终判定 |
| `records.jsonl` | 每次运行的原始记录：回答、逐句核对原始输出，以及每次调用的 Token、模型名和提示哈希 |
| `package.json` | 运行前固定的材料包：题目、每题检索资料、判定规则、两组提示的来源、费用估算 |
| `authorization.json` | 作者授权：预算、请求上限，以及绑定的材料包、题目和运行代码哈希 |
| `SHA256SUMS.txt` | 以上文件的 SHA-256 |

可以不调用模型，从 `records.jsonl` 重算结果：

```bash
python tools/competition/heldout_fix.py analyze --dir docs/competition/heldout-fix/20261014-deepseek
```
