## 三个阶段

在仓库根目录执行，输出目录必须与既有归档分开。具体参数以工具 `--help` 为准。

已有准备或运行目录一律拒绝覆盖；以下命令是用法示例，重复准备需指定新的目录。

### 1. 准备材料：不调用模型

```powershell
python tools/competition/judge_sensitivity.py prepare --output work/competition/judge-sensitivity/prepared
```

核对每条固定陈述、来源、完整上下文和证据差异。尤其确认：

1. 原始证据确实支持固定陈述。
2. 顺序变化仅调整片段位置，内容和数量不变。
3. 删除后是否还有其他片段、同义表达或条件组合支持该陈述。
4. 矛盾变体是否明确且唯一，是否还残留支持原陈述的片段。
5. 预期不明确的材料继续待确认，不能为了凑满数量直接批准。

作者实际确认后才填写姓名、实际日期及理由。AI 不代填人审，不把旧人审或过去的付费授权自动用于本实验。

### 2. 独立运行：本轮尚未授权

```powershell
python tools/competition/judge_sensitivity.py run --package <已确认材料.json> --authorization <本次授权.json> --output <新的独立运行目录>
```

运行前检查材料 SHA-256、提示及配置对应关系。费用单价未核实应为未知，不能沿用历史估算冒充当前报价。明确每次最大输出、预计输入量、请求上限和预算；实际扣费以供应商账单为准。

运行保护包括：

- 任一材料仍为 `pending`，立即拒绝进入运行阶段。
- 授权绑定本次材料、配置、提示和工具的 4 个源码文件哈希；工具或材料变化后旧授权失效。
- `outputDirectory` 绑定唯一独立目录，一份授权不能通过更换目录重复使用；目录已存在时不覆盖、不续跑。
- 单价或费用估算未知时不启动；请求完成后用量未知时保留记录并停止后续调用。
- 每个请求只尝试一次；取消、失败或异常后不得擅自整批重跑。

仅从现有环境读取密钥，不写入公开档案。没有额外可用性探测调用、不自动重试、不更换模型、不自动整批重跑；调用失败和未完整结束记录均保留。记录请求模型与实际返回模型、输入输出、用量及异常。预算估算保护不等于供应商费用自动封顶。

### 3. 离线分析：不调用模型

```powershell
python tools/competition/judge_sensitivity.py analyze --run <独立运行目录> --output <独立分析目录>
```

生成 `summary.json`、中文 `README.md` 和可本地打开的 `report.html`。相同输入重复分析应得到相同内容；报告保留每个条件、两个裁判、原始结果与异常，不把缺少结果记成通过。

## 如何解读

| 检查 | 报告内容 | 不能推出的结论 |
|---|---|---|
| 原始证据 | 判定与人工确认预期的符合数量 / 有效分母 | 总体准确率 |
| 原样重复 | 标签相同数量 / 有效配对数量 | 完整波动分布 |
| 顺序变化 | 标签相同数量 / 有效配对数量 | 对所有无关变换都稳定 |
| 依据移除 | 移除后依据不足数量与异常 | 完整文档不存在相关知识 |
| 明确矛盾 | 识别矛盾数量与异常 | 裁判不会受其他错误材料影响 |
| 引用定位 | 引文能否在指定片段找到 | 引文一定在语义上支持陈述 |

预期符合统计只使用人工确认后的变体，显示数量和有效分母。请求错误、解析失败、空内容、缺失和重复记录单列；不能默默缩小分母制造更好的结果。`insufficient` 无引用可能合理；`supported` 或 `contradicted` 缺少引用仍需核查。两个裁判的差异是待解释现象，不做模型综合排名。

本次只有 6 条定向陈述，不代表六个统计独立样本，也不能证明当前完整 Trace 流程更准确。结果全部符合预期时如实报告，不再挑选材料或调整提示寻找失败。

## 方法来源与贡献边界

- [RAGChecker](https://github.com/amazon-science/RAGChecker)：借鉴陈述级诊断与固定核查对象。
- [ALCE](https://github.com/princeton-nlp/ALCE)：引用存在性与支持质量分开检查。
- [CheckList](https://aclanthology.org/2020.acl-main.442/)：按输入变化定义需要保持或改变的行为关系。
- [ARES](https://arxiv.org/abs/2311.09476)：保留人工标注检查自动判断的边界，本轮不训练裁判或开展统计校准。
- [Anthropic 评测工程实践](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)：代码检查结构与引用，模型判断语义，人工确认实验预期；三者职责分开。
- [RAG 变形测试研究](https://arxiv.org/abs/2607.26843)：仅借鉴系统改变证据、检查行为关系的思想。本工具将实验对象限定为裁判，不声称复现该研究或与其结果同条件可比。

本实现的贡献是面向中文 RAG 的可回放裁判行为验证工具及材料组织。变形测试、引用检查与多裁判已有研究基础，不宣称全球首创，不使用“证明裁判可靠”“显著提高准确率”或未经同条件实验支持的优越性表述。

建议比赛表述：

> 平台支持固定陈述的证据变化测试，检查裁判判断是否随依据合理变化，并保留输入、输出和异常供人工复核。是否完成真实实验，以独立运行档案为准。
