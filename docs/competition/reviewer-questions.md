# 常见问题与回答口径

材料日期：2026-10-05。旧版本及`zh-sentence-v1`修复后5题验证均已完成；25题作者确认材料已锁定，并完成一次单模型正式运行。

## 这个项目有什么实际价值？

使用者可以从评测分数进入原始回答、检索上下文和逐句证据，观察模型差异，再核对门禁范围与阈值。开发者因此有材料分析失败原因，人工复核者也能保留对机器判断的分歧。

## 与直接使用 Ragas 相比，项目贡献是什么？

Ragas 提供评测指标。本项目整合文档处理、多模型问答、逐句记录、Quality Gate、报告和中文工作台，并提供绑定快照的人工核验材料。项目没有将第三方指标或模型能力声称为原创算法。

## 演示数据是真实的吗？现场会调用模型吗？

演示快照 `20260930-1958` 来自已有评测产物，包含 6 个问题、3 个模型、18 条回答。前端展示保存的原始内容，不在加载时调用模型。依赖准备后，无需模型密钥、Embedding 或后端即可在本地展示，不产生模型调用费用。金融 FAIL 来自另一场旧 CLI 运行，单独注明出处。

## 已完成的 13 条人工核验能证明什么？

作者 Kk 于 2026-10-05 逐条核对完整回答、参考答案、检索上下文、机器 Trace 与引用关系：一致 3、分歧 5、无法确认 5。AI 只辅助整理材料与定位证据，正式结论由作者确认。这是冻结 Demo 的定向作者自审，没有独立第三方复核，也没有据此重新校准门禁。

## 为什么只有 3 条一致？是否说明系统准确率很低？

这 13 条是围绕正常对照、拒答、空 Trace、抽取遗漏和引用支持等问题定向选择的回答记录。分歧可能针对证据覆盖或标签处理，无法确认可能来自关键材料缺失。该抽样与判定口径不能用于估计总体准确率。机器原判定和人工理由均保留，便于逐条回查。

## 模型给自己打分，会不会有偏差？

会存在同源偏差。当前后端的 Ragas 评测与 Trace 会复用相应被测模型，即 self-Judge。模型生成、陈述抽取与证据判断的错误可能相互影响；作者核验也不等于独立认证。历史快照没有完整保留确切裁判版本和提示词版本，不能事后推测补齐。独立裁判与第三方复核属于后续可投入方向。

## PASS 是否代表可以放心上线？

PASS 只说明指定正向样本的忠实度与上下文精度达到保存门槛。后端原始门禁采用首个有效评测模型；前端当前模型卡按照所选模型的保存指标检查。两者范围分别说明。0.8 尚无业务校准证明，门禁没有覆盖全部业务风险。

## 空 Trace 或引用匹配，能否证明回答正确？

空 Trace 可能与拒答、抽取或记录情况有关，不能证明没有幻觉。引用在检索原文中出现，仅支持检查引用出处，还需判断内容是否足以支持陈述。人工检查覆盖完整回答，避免只看机器已抽取的句子。

## 能自己复现结果吗？

无密钥 Demo 可以按 [演示指南](../demo/README.md) 打开同一冻结快照；同机独立前端副本的安装与构建记录见 [验收记录](validation.md)，不能称为另一台机器或全新操作系统验证，也不自动升级人工核验包的复现状态。

当前 Web API 已完成[旧版5题预跑](evidence/20261005T101847Z-pilot-c72cb679/README.md)及[修复后5题验证](evidence/20261005T131353Z-pilot-35f623cb/README.md)。后者111,996 token、65次完整调用，证明中文句子输入进入两个兼容指标并完成归档；门禁FAIL且不代表整体正确性。两轮5题记录不是浏览器点击全链路验收或旧Demo模型复跑；25题正式运行另有独立归档。复跑需要凭据、本地Embedding和对应环境；模型输出与分数可能波动。

## 为什么要准备 25 个问题？75 条回答够不够？

固定题集覆盖直接回答、多条件、材料缺失和错误前提，25题已由作者确认并完成一次单模型正式运行。它们来自同一法规节选，是不同问题而非统计独立样本。先完成单模型25条回答，三模型75条仅作为时间和预算允许后的扩展；Ragas与Trace会增加内部调用，预算不能按回答数计算。新增案例不构成总体可靠性证明，材料准备、运行与人审分别记录。启动前按[最终启动清单](formal-run-checklist.md)确认。

## 中文兼容修正是否改变了评分，是否覆盖旧结果？

`zh-sentence-v1` 只让中文非空句子进入原陈述抽取提示，保留 Ragas 0.1.21 的评分公式、权重及英文路径。当前 CLI / Gradio 经 `main.py.run_pipeline` 委托共享后端编排，因此新运行同样会使用兼容层；保留的 `_legacy_run_pipeline` 不是正常入口。旧 run、冻结 Demo 和人工核验数据没有重算。新版本必须独立归档，得分可能升降，不能把离线通过当作裁判正确或兼容版真实运行成功。

## 目前能作为多人在线生产平台使用吗？

当前产品定位为本地评测与结果展示。后端同步执行，现有单进程保护不能替代完整任务队列、取消、鉴权和资源隔离。若后续面向多人在线使用，需要单独推进这些工程能力。

详细边界见 [评测结果可信度与限制](../evaluation-credibility.md)；三分钟展示顺序见 [演示脚本](demo-script.md)。
