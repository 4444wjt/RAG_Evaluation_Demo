# 鲁棒性体检：改动资料，看应用和核对是否真的依据资料

[门禁可信度](../gate-credibility.md)第三问「证据变了，裁判会跟着变吗」是一次性实验：6 条人工挑选的陈述，30 项人工确认的材料。本目录把它做成一个可用于任何 RAG 应用的功能，并补上 [RGB](https://github.com/chen700564/RGB) 的加噪、应拒答、反事实三种情形。

工具不需要人工挑选，也不需要人工确认材料。它自动定位每题的依据资料，构造五种资料条件，分别检验两侧：

- **核对侧**：回答不变，只换资料重新逐句核对（`trace_hallucinations`）。检验裁判是否跟着证据走。
- **生成侧**：用改动后的资料重新作答，再逐句核对。检验被测应用会不会被资料带偏。生成侧默认用平台的问答提示（`rag_answer`）作答，也可以接入你自己的应用。

体检不新增门禁指标，也不改门禁规则；结果只说明应用与核对在资料变化时的表现。

## 交付状态

**已运行一次（2026-10-13）。** 体检对象是 [25 题正式运行](../evidence/20261005T144504Z-full-39511424/README.md) 中门禁所用的 20 道正向题，领域为《存款保险条例》节选。

- **授权**：付费调用经用户在会话中单独授权，预算 ¥5，最多 260 次请求，不重试。材料包与运行代码的 SHA-256 均绑定在 [authorization.json](20261013-formal-run/authorization.json) 中。
- **调用**：260 次请求全部返回，没有失败，167 / 167 项任务完成。
- **费用**：按返回用量估算 ¥0.47（输入 146,676 token，输出 21,496 token），不是账单。运行前估算的上限是 ¥2.04。
- **模型**：请求模型为 `deepseek-chat`，服务端返回的模型名为 `deepseek-flash`，260 次均如此。核对与作答都直接调用生产代码，没有另写提示词。
- **输入**：只读取冻结证据（`api-response.json`，SHA-256 `76986504…fadb9d`），不改动它。

## 五种资料条件

| 条件 | 怎么改资料 | 核对侧应当 | 生成侧应当 | 可构造 |
|---|---|---|---|---|
| 原样 | 不改，作为同一次运行内的对照 | — | — | 20 / 20 |
| 打乱 | 只改变资料顺序 | 结论不变 | 结论不变 | 20 / 20 |
| 加噪 | 插入 2 条其他题的资料（与本题依据无逐字重合） | 结论不变 | 不被噪声带偏 | 20 / 20 |
| 移除依据 | 去掉含依据的资料，用其他题的资料补足条数 | 标出无依据 | 拒答 | 20 / 20 |
| 反事实 | 只改依据原文里的数字和情态词 | 标出矛盾 | 跟随资料或拒答，不沿用原值 | 13 / 20 |

反事实有 7 题无法构造：这些题的依据片段里没有可改的数字或情态词。工具对这类题如实跳过，不硬造。

## 方法

**依据定位不用模型。** 回答（拒答时改用参考答案）与资料逐字重合的片段，满足以下条件即视为依据：

- 至少 5 个字（去掉标点后比较）；
- 在全部资料中出现的条数不超过 20%，用来排除「存款保险」这类到处都有的词。

含这类片段的资料就是依据资料。本次输入共 11 条不同资料，所以一个片段最多出现在 2 条资料中。

**干扰资料**取自其他题，需要同时满足：

- 不含本题依据片段；
- 与本题回答、参考答案没有共同的少见片段。

**反事实只改依据片段内的词。** 改动有两类：

- 数字：翻倍；后接「年」的年份加一；
- 情态词：应当→无需、包括→不包括、不适用→适用、有权→无权等，共 12 组。

每处改动都记录改前、改后，例如「50万元 → 100万元」「应当 → 无需」。本次 13 题共改了 7 处数字、10 处情态词。

**构造可复现。**

- 随机性只来自种子（20261013）、题号和条件；构造与被检的裁判无关。
- 付费运行前，材料包 `package.json` 可以逐条检查。
- 用同一输入重新执行 `prepare`，得到的材料与归档完全相同，只有生成时间不同。

**判定规则**：

- **核对侧**：以同一次运行的「原样」条件为对照。拒答的回答没有可核对的陈述，核对侧跳过。本次 20 题中 4 题原样拒答，所以核对侧是 16 题。
- **生成侧**：先判断是否拒答，再看核对结果。改了数字的题，再按字符串判断回答用的是哪一个值：跟随新值、沿用原值、两者都有、都没有，或拒答。
- 比例都给出 Wilson 95% 区间。

## 结果

### 核对侧：58 项检验中 57 项符合预期

| 条件 | 应当 | 结果 |
|---|---|---|
| 原样 | — | 16 个回答，核对标出 0 个（对照） |
| 打乱 | 结论不变 | 16 / 16 不变 |
| 加噪 | 结论不变 | 16 / 16 不变 |
| 移除依据 | 标出无依据 | 16 / 16 标出（区间 80.6%–100%） |
| 反事实 | 标出矛盾 | 9 / 10 标出，且都判为矛盾（区间 59.6%–98.2%）；改数字 4 / 4，改情态词 5 / 6 |

**唯一未达预期：D09。** 改动落在修饰语上：「应当交纳的保费」改成「无需交纳的保费」。核对引用了改动后的原文，仍判为支持。这一改动本身语义别扭，但按规则如实计为未标出。

### 生成侧：没有一题沿用原值顶替资料

| 条件 | 应当 | 结果 |
|---|---|---|
| 原样 | — | 拒答 4 / 20；作答的 16 题核对标出 0 题 |
| 打乱 | 结论不变 | 拒答 2 / 20；作答的 18 题核对标出 1 题（D07） |
| 加噪 | 不被噪声带偏 | 拒答 4 / 20；作答的 16 题核对标出 2 题（D07、F02） |
| 移除依据 | 拒答 | 拒答 19 / 20（95%，区间 76.4%–99.1%），比原样新增 15 题；D01 仍作答 |
| 反事实 | 跟随资料或拒答 | 拒答 8 / 13（新增 5 题）。作答 5 题，全部依据改动后的资料，核对标出 0 题。改了数字的 7 题：跟随新数值 3 题，拒答 4 题，沿用原值 0 题 |

值得注意的结果，均已逐条看过原文：

- **D01 · 移除依据后仍作答**：模型把第三条对存款保险的定义当成「目的」作答，核对按字面判为有依据。逐句核对只查有无依据，不查是否答对了题。
- **D07 · 打乱、加噪后编造条号**：资料片段没有写条号，回答却注明「第四条」「第二条」。核对分别标为无依据、矛盾，都标得对。
- **F01、F05 · 打乱后改为作答**：两道错误前提题在原样资料下拒答，只打乱资料顺序，就改为依据原文纠正前提。这类题的拒答对资料顺序敏感，与 [失败归因](../../gate-replay.md#失败归因该修检索还是生成) 中「提示词只给了拒答出口」的结论一致。
- **F02 · 加噪后的误判**：回答本身正确，核对把「……这一说法不对」判为矛盾，是否定叠加句上的误判。

工作台「鲁棒性体检」页列出逐题矩阵与以上说明。页面数据由 [`build_robustness_fixture.py`](../../../tools/competition/build_robustness_fixture.py) 从本归档生成，生成时做三项核对：文件哈希、材料包与授权的绑定，以及能否用材料包和逐条调用记录重新算出全部汇总。任何一项对不上，都拒绝生成。

## 解读与局限

1. **核对侧随证据变化。** 证据被移除时 16 / 16 标出；证据被改成反事实时 9 / 10 判为矛盾。打乱、加噪不改变结论。这与第三问在 6 条定向陈述上的结果一致，现在扩展到了全部 16 个非拒答回答。
2. **改动落在修饰语上时可能漏判**（D09）。情态词翻转并不总是翻转整句的主张，这类改动对核对更难。
3. **应用基本依据资料作答。**
   - 移除依据后 95% 拒答；
   - 反事实条件下没有一题沿用原值顶替资料。
   - 但「移除依据就拒答」不等于「答得对」：D01 用不相干的条文凑出了回答，而逐句核对查不出这类答非所问。
4. **拒答对资料顺序敏感**（F01、F05），这是问答提示词层面的问题，不在核对。
5. **范围有限。**
   - 单领域、20 题、一次运行，每个请求只运行一次，没有重复测量。
   - 只用了一个裁判模型（服务端返回 `deepseek-flash`），且作答与核对是同一个模型。
   - 依据定位基于逐字重合，改写式的依据可能定位不到。这时移除依据会留下实际含依据的资料，结果偏保守。
   - 反事实只覆盖数字和 12 组情态词，不覆盖实体替换、时间顺序等改动。

## 在你的 RAG 应用上体检

```bash
python scripts/robustness_check.py prepare   --input <评测结果.json | 题目.jsonl> --dir <工作目录>
python scripts/robustness_check.py authorize --dir <工作目录> --by <授权人> --budget <元>
python scripts/robustness_check.py run       --dir <工作目录>
python scripts/robustness_check.py analyze   --dir <工作目录> --output <归档目录>
```

**输入**有两种格式：

- **平台评测结果**（`api-response.json`）：取门禁所用的主模型，只取正向题。`--case-manifest` 可以把行号换成题号。
- **JSONL**：每行一道题，格式为 `{"id", "question", "contexts": [...], "answer", "ground_truth"}`；`answer` 与 `ground_truth` 至少要有一个。没有 `answer` 时，核对侧跳过该题，生成侧照常运行。

**接入被测应用（可选）。** 加 `--generator-endpoint <URL>` 后，生成侧改为调用你的应用：

```text
POST <URL>   {"question": "…", "contexts": ["…", "…"]}
返回         {"answer": "…"}
```

- 应用须直接用传入的 `contexts` 作答，不能再自行检索，否则体检无法控制资料。
- `--endpoint-token-env <变量名>` 指定存放访问令牌的环境变量，令牌以 Bearer 方式发送，不写入任何文件。
- 被测应用自身的调用不计入费用估算。

**费用控制。**

- `prepare` 不调用模型，只构造材料并给出偏保守的费用上限。
- `authorize` 把材料包与运行代码的哈希写入授权文件。
- `run` 运行前核对授权、材料包与代码，每个请求只尝试一次，不重试，达到预算或请求数上限即停止。中断后可续跑，不会重复付费。
- 核对侧裁判可以用 `--judge-model`、`--judge-base-url`、`--judge-key-env` 更换。

工具的离线测试见 [`tests/test_robustness.py`](../../../tests/test_robustness.py)。测试覆盖依据定位、五种条件的构造、反事实改动、汇总口径、授权绑定、预算停止、续跑和接口接入，不调用模型，也不访问网络。
