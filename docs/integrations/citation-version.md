# 引用版本检查（CLML）

上传英国官方 CLML XML，填写所需视图日期、片段查询日、地域和语言，核对原件明示字段是否满足这些要求。结果逐条保留冲突、缺失和待复核项，并可下载报告与自包含复核包。

适用对象是持有 CLML 资料、需要核对引用版本条件的使用者。普通 HTML、PDF、中文法规、引文语义与法律适用不在本接口范围；它也不改变既有 RAG 质量门禁。

## 网页使用

按[前端本地启动说明](../../frontend/README.md)启动前后端，然后打开 `http://127.0.0.1:5173/#/lab/citation-version`，或在“资料准备”组选择“引用版本检查”。公开只读/静态演示不接收文件。

1. 上传 XML，查看观察到的文档和条款信息。上传至当前本地服务处理，不保存到服务器文件，不调用模型，也不访问原件中的网络地址。
2. 明确选择自己要核对的条款，填写期望日期、地域、语言。原件观察值与用户要求分别显示；文件内部一致不证明它就是用户原本应引用的资料。
3. 运行检查，查看每条结果的字段值与原文路径。字段冲突时核对自己的要求或更换资料；待复核项需要补证据，不能自动当成通过。
4. 修改输入后重新检查。旧报告属于旧输入，不会自动沿用于新文件或新要求。
5. 下载 HTML 阅读报告，或下载 JSON 复核包供另一台本地环境重新计算。复核包含原始文件内容及引用要求，分享前自行确认可以公开。

## 结果含义

| 轴 | 所检查的内容 | 不代表什么 |
|---|---|---|
| 身份与视图绑定 | 文档/条文标识、所选视图及声明日期/语言是否与要求相符 | 不证明来源真实性、引文语义或法律有效 |
| 片段元数据 | 明示地域、片段起止范围及未解决的显式条件 | 不代替复杂法律作用与地域适用判断 |
| 历史可知性 | 本版缺少可信历史公开记录，保留 REVIEW | 今天取得的历史视图不证明当年已有这些字节 |

七个分项均保留：identity、view、snapshot_date、language、extent、fragment_interval、conditions。MATCH只表示本契约所列字段相符；MISMATCH表示有明示冲突；REVIEW表示信息或支持范围不足；INVALID_INPUT表示输入无法执行检查。没有总PASS。

计数中的“冲突”“字段待复核”“历史可知性待复核”允许重叠，不能相加为互斥分母。每条输入都进入报告，单条错误不静默丢弃；重复ID或整个包格式错误则明确拒绝整包。

## 离线复核

使用生成报告时对应版本的源码，在仓库根运行：

```powershell
.\venv\Scripts\python.exe -B scripts/citation_version_check.py verify --bundle citation-version-bundle.json
```

退出0且 `verified=true` 表示重新计算的完整报告与包内保存报告相同；不证明这些资料或用户要求真实、适用或具有法律效力。源码或契约版本不同会改变绑定，不能跳过差异强行称一致。

普通批处理也可直接一次运行多条引用，使用与网页相同的B1核心：

```powershell
.\venv\Scripts\python.exe -B scripts/citation_version_check.py check --input requests.json --report report.json --bundle bundle.json
```

输出文件须尚不存在，且与输入和其它输出路径不同。退出2表示输入/文件操作错误，退出3表示复核不一致；check退出0仅表示检查完成，仍须阅读冲突与待复核结果。

## HTTP与绑定边界

- `POST /citations/versions/inspect`：`CitationVersionFilesV1`，观察文件字段，不自动生成用户期望。
- `POST /citations/versions/check`：`CitationVersionCheckV1`，多个文件与带稳定ID的明确引用需求。
- `CitationVersionBundleV1`：原请求与 `CitationVersionReportV1`，原件以base64保留；复核时重算全部结果，不仅比较自报哈希。
- 最大10份文件、20条引用；原始文件单份/合计5MiB；请求体8MiB；XML深度128、节点50000；JSON嵌套128。超限拒绝，不截断取成功子集。
- 为限制小 XML 引发的展开，构树前以无命名空间展开的流式预检核对元素/属性展开名总预算16MiB；路径预算16MiB，单份证据预估4MiB、整批48MiB。单份超限记录为无效输入，整批超限返回413。完整报告上限64MiB，自包含复核包上限128MiB；请求本身合法但无法形成可复核包时也拒绝，不截断证据。
- 文件SHA256覆盖原始字节，与旧来源登记的 `sha256-lf` 不同；BOM、CRLF与LF不被悄悄改写。同名文件按不同ID和字节绑定，不按名称关联。
- 报告绑定本进程加载的规则与封装源码版本。运行中源码变化或变得不可读时返回409；请由本地服务维护者重启对应版本再检查，不能把旧执行结果标成新版本。
- DTD/ENTITY、未知文件ID、错误哈希、重复ID、格式/编码错误与缺失信息均有明确诊断。核心只使用B1，研究弱对照及消融不作为网页选项。

这是一项确定性规则与报告工作流的工程组合。现阶段未证明人工节时、真实采用率、算法创新或相对成熟同类的性能优势。

哈希证明文件的字节绑定，不证明语义正确，也不证明模型输出可复现。本功能不调用模型；固定输入与对应源码版本的复算范围，仅限这里的确定性版本字段检查。可用 `Get-FileHash -Algorithm SHA256 -LiteralPath .\your-source.xml` 核对原始XML，与报告中对应文件ID的哈希比较。
