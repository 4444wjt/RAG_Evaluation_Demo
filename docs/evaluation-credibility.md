# 评测结果可信度与限制

本项目展示的是可回查的评测材料与规则检查结果，不是模型可靠性的认证。演示使用冻结快照；人工核验结论与机器结果分别保存，不相互覆盖。

## 1. PASS 说明什么

演示快照 `20260930-1958` 包含 **6 个独立问题、3 个模型、18 条回答**。每个模型回答相同的 3 个正向和 3 个负向问题。

| 展示对象 | 判定范围 | 不代表什么 |
|---|---|---|
| 当前模型结论卡 | 所选模型的 3 条正向用例；正向忠实度与正向上下文精度均达到保存门槛 `0.8` 时显示 PASS | 全部 18 条回答正确、负向用例全部通过或所有指标优秀 |
| 原始评测门禁 | 原评测流程按首个有效评测模型的两项正向指标判定，保存原始 `gate_passed` | 对每个模型独立判定后的合并结论 |
| WARNING | 当前模型的正向指标或阈值缺失，无法完成展示检查 | 已确认失败或可按零值补算 |

切换模型只改变当前卡片的展示检查，不改写原始门禁。快照保存了阈值与指标，但缺少原始门禁说明 `gate_message`；页面中的指标对照解释不替代缺失的原始说明。

这套门禁不检查所有业务风险，也不因任意一条逐句判定直接拦截。现有 `0.8` 阈值尚无业务校准证明，PASS 不代表模型总体可靠性或生产就绪。

## 2. 逐句记录与 LLM Judge 的边界

### 三层口径：引用定位、语义支持、事实正确

逐句核对的结论分三层，各层回答的问题不同，不能互相替代。本项目的页面和文档按这三层的说法表述。

| 层 | 回答的问题 | 平台怎么做 | 可信程度 |
|---|---|---|---|
| **引用定位** | 判定给出的证据，能否在检索原文里逐字找到 | 代码检查：「有依据」「事实错误」两类判定必须附证据，证据须是检索原文中连续、逐字一致的片段，否则整条判定被丢弃（[`trace.py`](../backend/services/trace.py)） | 确定性检查，不依赖模型 |
| **语义支持** | 这句陈述能否仅凭那段原文推出 | 模型裁判判定；门禁所用的忠实度（Ragas）也属于这一层 | 有误差：逐句核对在 ANAH 上对有幻觉句子的召回为 0.89；门禁裁判经 3 位非作者标注，按事先写定的两人口径分析其中两人，灵敏度 95.0%、特异度 100%（仅 6 条） |
| **事实正确** | 陈述在现实中是否正确 | 不检查 | RGB 反事实题：资料写错时，照抄的回答 11 题只标出 3 题 |

- 引用已定位，不等于语义支持；语义支持，不等于事实正确。
- 逐句判定里的「事实错误」指与检索资料矛盾，属于语义支持层，不是与现实核对的结果。
- 已抽取的陈述全部有依据，不等于回答没有遗漏的陈述（见下文「可能有抽取遗漏」）。

出处：[外部基准验证](competition/external-validation/README.md)、[人工标注结果](competition/judge-calibration/20261014-annotation-V/README.md)。

### 来源版本

- **登记内容：** 在独立的来源登记表中记录制定机关、来源发布机构、公布与施行日期、取得日期、原文或节选范围，以及适用对象、地域和条件；未知字段保持为空。虚构示例资料明确标注不是权威来源，登记信息不参与门禁计算。
- **状态顺序：** 未登记，或制定机关、公布日期、施行日期、来源网址、取得日期任一缺失，显示「缺少版本」；这些字段齐备后，适用对象、地域、条件任一缺失，或节选未列出范围，显示「适用范围待确认」；其余显示「信息齐备」。文号和修订说明只展示，不参与判定。「信息齐备」不代表资料现行有效；实时结果缺少资料哈希时，不能仅按文件名与登记表对应。
- **哈希边界：** 资料按 LF 归一化 SHA-256 关联，归档保留原始字节哈希。哈希只证明资料与记录的版本一致、文件未变，不能证明内容正确或仍然有效；本功能不核查资料是否现行有效。

### Trace 能支持的检查

Trace 保留机器抽取的陈述、原判定和证据，便于对照原始回答与检索上下文。人工检查仍须覆盖完整回答，不能只检查机器已经抽取的句子。

- **可能有抽取遗漏：** 未被抽取的陈述不会自动出现在逐句判定中。
- **空记录不是安全证明：** 空 Trace 可能与拒答、抽取或记录情况有关，不能推定回答没有幻觉。
- **引用已定位不等于语义支持：** 引用确实出现在检索原文中，仍须检查它是否足以支持该陈述。
- **参考答案也有范围：** 参考答案、检索文本与拒答处理需要分别核对，不能用单个标签代替完整回答检查。

### Judge 的已知信息与缺失信息

LLM Judge 的结果依赖裁判模型、提示词、输入上下文及运行条件；生成与裁判过程可能存在偏差。不能将一次模型判断作为独立的事实认证，也不能把不同运行的分数直接当作严格可比的实验结论。

| 当前保留 | 当前未完整保留或未证明 |
|---|---|
| 快照运行时间、文档名、测试集来源、回答模型标识、保存阈值、指标、原始回答与 Trace | 历史裁判模型的确切版本、提示词版本、完整运行环境，以及这些条件下的独立复跑证明 |

回答模型名称不能用于推定裁判模型版本。缺失的历史信息不通过推测补写。

## 3. 人工核验范围与录入规则

“评测验证”页定向预选 **13/18 条回答**，关联 **12/19 条机器逐句记录**，用于检查正常对照、抽取遗漏、拒答、空 Trace 和引用支持等情况。13 条是回答记录数，不是独立问题数、随机抽样结果或总体准确率的分母。

当前核验包的 13 条记录已由 AI 辅助整理材料、作者人工逐条核验完成：一致 3、分歧 5、无法确认 5。页面的“已检查”包含一致、分歧、无法确认，只表示检查已完成，不表示机器判定已获认可。该核验仅覆盖冻结 Demo 的 13 条定向样本，不代表总体准确率、独立认证或模型复跑验证。不生成准确率或可信度评分。

### 四种状态

| JSON 状态 | 页面状态 | 使用条件 |
|---|---|---|
| `pending` | 未核验 | 尚未完成检查；`reviewer`、`reviewedAt`、`answerReview` 保持 `null`，`statementReviews` 保持空数组 |
| `agree` | 一致 | 已检查完整回答、抽取、拒答与证据，认可机器原判定；无明确遗漏、拒答问题、无法确认项或不同逐句判定 |
| `disagree` | 分歧 | 至少一项有明确分歧，记录具体理由；即使逐句标签相同，也可能在抽取或证据支持方面有分歧 |
| `uncertain` | 无法确认 | 已完成检查，但关键依据不足，无法形成确定结论；记录缺失依据与未决项 |

同时存在明确分歧和未决项时，汇总为 `disagree`，在理由中保留未决项。汇总状态由真实核验者填写，不根据标签自动认定结论正确。

### 在现有 JSON 中录入

只修改 [`frontend/src/fixtures/credibility-review.json`](../frontend/src/fixtures/credibility-review.json) 中已有记录的人工字段。页面只读，不提供表单、导入或存储服务。

1. 在演示工作台进入“评测验证”，按模型和用例找到记录，对照完整问题、回答、参考答案、检索原文与机器陈述。参考答案可在冻结 [`demo.json`](../frontend/src/fixtures/demo.json) 的对应记录查看。
2. 保持 `schemaVersion`、`snapshotVersion`、`snapshotSha256`、13 个 `modelId` / `rowIndex` 组合及核验重点 `focus` 不变。`rowIndex` 从 0 起算，界面用例编号从 1 起算。
3. 完成检查后，填写下表中的真实人工材料。未完成的记录继续保持 `pending`，不代填结论。
4. 重新打开或刷新页面，检查状态、人工结论与机器原判定是否分别呈现。材料格式无效、索引错误或快照不匹配时，页面不展示核验统计。

| 字段 | 填写规则 |
|---|---|
| `reviewer.name` / `reviewer.role` | 真实核验者姓名；`author` 为作者自审，`independent` 为实际独立复核。AI 辅助整理不能标为独立人工复核 |
| `reviewedAt` | 实际完成日期，格式为 `YYYY-MM-DD` |
| `answerReview.extraction` | `complete` 完整、`missing` 有遗漏、`not_applicable` 不适用、`uncertain` 无法确认；根据完整回答判断 |
| `answerReview.refusal` | `reasonable` 合理、`questionable` 有问题、`not_applicable` 不适用、`uncertain` 无法确认 |
| `answerReview.reason` | 回答级检查理由；描述遗漏、拒答、分歧或依据不足的具体位置 |
| `statementReviews` | 对每条机器原始陈述填写一次，不新增、遗漏或重复索引；空 Trace 保持空数组，仍填写回答级检查 |
| `statementIndex` | 对应原始 Trace 中从 0 起算的陈述索引 |
| `humanVerdict` | `supported` 有依据、`fact_error` 事实错误、`fabrication` 无依据编造、`not_applicable` 不适用、`uncertain` 无法确认 |
| `reason` / `evidence` | 每句人工理由必填；证据为实际原文摘录或 `null`，不编造证据 |

校验会拒绝 `agree` 与抽取 `missing` / `uncertain`、拒答 `questionable` / `uncertain`、逐句 `uncertain` 或不同于机器的逐句判定并存。校验只检查材料结构、明确矛盾和快照绑定，不替代人工审查，也不能证明填写内容真实或结论正确。

**不要修改机器结果：** 原始回答、Trace、指标和门禁继续来自冻结快照。SHA-256 用于确认材料绑定的文件版本，不是判断正确性的认证。

## 4. 如何阅读历史 FAIL 案例

金融案例 `20260928-1313` 来自旧 CLI 的独立运行，在“评测验证”页展开“历史失败案例”可查看：问题 → 原始回答 → 逐条指标 → 原始 FAIL → 指标对照分析。

- 第二个问题的保存上下文精度为 `0.3333333333`，界面显示 **33.3%**。
- 原归档正向忠实度为 `1.0`，达到 `0.8` 门槛；正向上下文精度均值为 **`0.7778`**，低于 **`0.8`**，原始门禁保存为 FAIL。
- 使用保存值作对照，不重新计算、替换原始均值或制造失败。低上下文精度不等于已经确认回答存在事实错误。

原始数据及文件 SHA-256 保存在 [`financial-failure-case.json`](../frontend/src/fixtures/financial-failure-case.json)。该案例缺少原始门禁说明与逐句 Trace；指标对照分析不能补写这些缺失记录，也不证明人工核验触发了门禁拦截。

历史案例来自当时 CLI 版本的独立运行，不能仅按当前代码推断其具体执行条件。当前 CLI / Gradio 已经 `main.py.run_pipeline` 委托 `backend.core.pipeline.evaluate`，与 Web API 共享编排；模型工厂和入口校验仍有区别。保留的 `_legacy_run_pipeline` 不是当前正常入口。历史案例不作为当前 API 的复跑证明，不并入 Demo 的 18 条回答或 13 条人审范围。

## 5. 当前核验与运行边界

| 检查项 | 当前边界 |
|---|---|
| 13 条人工核验 | 已完成作者自审（一致 3、分歧 5、无法确认 5）；仍不能宣称人机一致或通过独立复核，不代表总体准确率或模型复跑验证 |
| 门禁规则人工核对 | `gateRuleReview` 尚未录入完成材料；保存阈值也没有业务校准证明 |
| 干净环境快照重现 | 同机独立前端副本已有安装与构建记录，见[验收记录](competition/validation.md)；`reproduction.snapshotReplay` 的人审状态仍未升级，不能称另一台机器验证 |
| 真实模型复跑 | `reproduction.modelRerun` 尚未录入完成材料；加载快照不调用模型、不证明可复现相同结果 |
| 旧版本5题真实API预跑 | 已完成草稿消耗预跑，106,955 token、64次逻辑调用；不证明浏览器评测闭环、旧Demo模型复跑或Judge正确 |
| 中文兼容版本 | `zh-sentence-v1` 保持指标公式与门禁；修复后5题真实验证中15条抽取提示均包含非空中文句子输入，新旧run仍不能混为相同条件 |
| 修复后5题验证 | D06、C02、C05、N01、F03；111,996 token、65次完整调用；正向Faithfulness 0.6000低于0.8而FAIL。该结果是草稿技术验证，不是25题正式结果 |
| 25题正式实验 | 作者Kk已确认题集；2026-10-05完成一次单模型运行，25/25回答、五项指标有效，Gate因正向Faithfulness 0.7375<0.8而FAIL；新分析仍为AI辅助、待人工确认，不继承旧13条作者核验；证据见[正式运行包](competition/evidence/20261005T144504Z-full-39511424/README.md) |
| 广泛场景与总体可靠性 | 当前样本覆盖有限，不是正式 Benchmark，未建立总体准确率或生产风险结论 |

门禁规则核对、快照展示重现和真实模型复跑这三项档案检查使用 `unverified`（未验证）、`verified`（已人工检查）或 `uncertain`（无法确认），分别填写真实核验者、实际日期与说明。三项检查不能互相替代；未完成时人工字段保持为空。

5题预跑的来源、消耗和异常解释见 [独立证据包](competition/evidence/20261005T101847Z-pilot-c72cb679/README.md)。其中低分、拒答、空Trace与缺失指标均保留，不以兼容修正追认旧答案正确，也不更改人工核验状态。

演示入口与操作顺序见 [演示指南](demo/README.md)，当前流水线与兼容入口见 [技术架构](architecture/README.md)。


## 6. 25题正式运行边界

本次25题是同一金融材料的固定场景实验，不是跨领域 Benchmark、统计独立样本或总体准确率证明。运行保存请求/实际返回模型、中文适配版本、提示与Trace源码哈希、contexts、用量、指标、报告和脱敏文件哈希。F类拒答与N类空/非空Trace差异、C02/D09/C03/D08的指标观察均需人工复核；AI辅助分析不会自动写入 `credibility-review.json`。Trace或人工意见不直接触发当前 Quality Gate。
